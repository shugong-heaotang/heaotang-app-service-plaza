# 服务广场协作与交付规范

本文档作为服务广场后续推进的统一协作规范。各板块负责人、APP 总架构负责人、平台集成负责人均按本文档执行。

服务广场架构已经定版。当前阶段的重点不是重新讨论架构，而是围绕既定架构快速完成内容接入、功能联调、测试验收和上线准备。

## 一、总体原则

1. 服务广场结构已定版，原则上不再调整核心信息架构、模块顺序和主入口关系。
2. 各板块不能自行修改服务广场页面结构，必须通过统一接入流程提交内容、入口、接口和验收标准。
3. 平台集成负责人统一负责跨板块接入、接口联调、路由、权限和发布协调。
4. APP 总架构负责人负责最终技术边界、页面结构边界和重大变更裁决。
5. 所有重要沟通必须沉淀到看板、接口清单、问题清单、交接记录或决策记录中，不能只停留在微信群或口头沟通。

## 二、角色与职责

### 1. APP 总架构负责人

主要职责：

- 维护服务广场整体架构和页面边界。
- 决定哪些能力进入服务广场主入口，哪些能力进入更多服务。
- 审核跨板块变更、公共能力抽象和重大技术调整。
- 维护架构决策记录，避免反复讨论已经确定的事项。

### 2. 平台集成负责人

主要职责：

- 维护服务广场统一接入清单。
- 统一处理接口、路由、权限、埋点、发布和联调问题。
- 发现并协调各板块之间的冲突，例如入口重复、字段不一致、权限边界不清。
- 组织联调会，推动阻塞问题关闭。

### 3. 各板块负责人

主要职责：

- 对本板块内容、功能、业务规则、页面跳转和验收标准负责。
- 按统一模板提交板块接入信息。
- 按统一节奏更新进度、风险和阻塞。
- 负责本板块交付质量，不把未确认的问题推给平台集成环节。

## 三、统一工作台

项目当前按单人决策、agent 协同和本地台账推进，不强制建立飞书、企业微信、钉钉、语雀、Notion、Jira 或禅道等外部工作台。agent 协同方式、角色分工和台账规则见 `docs/project-management/service-plaza/collaboration-tool-setup.md`。

本地台账至少包含以下五个区域：

### 1. 总进度看板

字段要求：

| 字段 | 说明 |
| --- | --- |
| 板块名称 | 例如生命导航、俱乐部联盟、健康大管家、活动广场 |
| 负责人 | 本板块唯一责任人 |
| 当前状态 | 未开始 / 开发中 / 联调中 / 测试中 / 已完成 / 阻塞 |
| 计划完成时间 | 明确到日期 |
| 当前风险 | 影响交付的风险 |
| 下一步动作 | 下一步要完成的具体动作 |

### 2. 接口与集成清单

由平台集成负责人维护。

字段要求：

| 字段 | 说明 |
| --- | --- |
| 板块名称 | 对应业务板块 |
| 入口名称 | 服务广场展示名称 |
| 跳转页面 | 点击后进入的页面或路由 |
| 需要接口 | 涉及的接口名称或地址 |
| 权限要求 | 是否登录、是否会员、是否管理员 |
| 联调状态 | 未定义 / 已定义 / 联调中 / 已通过 |
| 问题记录 | 当前接口或集成问题 |

### 3. 问题与阻塞池

所有阻塞必须登记到问题池。群里提到的问题，如果影响进度，也必须同步到问题池。

字段要求：

| 字段 | 说明 |
| --- | --- |
| 问题描述 | 一句话说明问题 |
| 所属板块 | 问题归属 |
| 责任人 | 当前解决责任人 |
| 影响范围 | 影响哪个板块或哪个流程 |
| 解决期限 | 明确到日期 |
| 当前状态 | 待处理 / 处理中 / 已解决 / 需裁决 |

### 4. 决策记录

由 APP 总架构负责人维护。

以下事项必须记录：

- 服务广场结构变更。
- 主入口名称、顺序、层级调整。
- 跨板块公共能力设计。
- 权限、账号、支付、消息、数据同步等公共规则。
- 与既定架构不一致但必须特殊处理的例外事项。

### 5. Handoff 交接记录

每个板块在阶段切换时必须提交 handoff 记录。没有 handoff 记录，默认不能进入下一阶段。

## 四、Handoff 交接机制

Handoff 是本项目的强制交接机制，用于保证每个板块从需求、开发、联调、测试到上线都能清楚交接。

### 1. 基础 handoff 模板

```text
板块名称：
当前负责人：
当前阶段：
已完成内容：
未完成内容：
依赖对象：
阻塞问题：
下一步动作：
计划完成时间：
需要谁确认：
```

### 2. 开发交给联调时必须补充

```text
接口文档地址：
页面路由：
测试账号：
测试数据：
权限要求：
已知问题：
联调通过标准：
```

### 3. 联调交给测试时必须补充

```text
测试范围：
不测试范围：
主要测试路径：
异常场景：
已知风险：
验收负责人：
验收通过标准：
```

### 4. 测试交给上线时必须补充

```text
上线内容：
上线时间：
影响板块：
回滚方案：
上线后验证项：
上线负责人：
最终确认人：
```

## 五、沟通节奏

### 1. 每日站会

频率：每天一次，控制在 15 分钟内。

只讨论三件事：

- 昨天完成了什么。
- 今天要完成什么。
- 当前有什么阻塞。

不在每日站会上展开长时间方案讨论。需要深入讨论的问题，进入专题会或问题池。

### 2. 每周集成会

频率：每周至少一次。

主持人：平台集成负责人。

重点内容：

- 接口定义是否完整。
- 跨板块联调是否阻塞。
- 权限、路由、账号、数据是否一致。
- 哪些问题需要 APP 总架构负责人裁决。

### 3. 每周架构会

频率：每周一次，必要时临时召开。

主持人：APP 总架构负责人。

只处理以下问题：

- 是否影响服务广场既定结构。
- 是否需要新增公共能力。
- 是否涉及多个板块的技术边界。
- 是否需要形成新的架构决策记录。

### 4. 阶段验收会

每个阶段结束前召开。

验收内容：

- 看板状态是否真实。
- Handoff 是否完整。
- 接口联调是否通过。
- 测试路径是否覆盖主流程。
- 是否具备进入下一阶段的条件。

## 六、交付优先级

当前阶段按主链路优先，不追求所有功能一次性完整。

第一优先级：

1. 用户进入服务广场。
2. 用户看到核心服务和常用服务入口。
3. 用户进入板块详情页。
4. 用户完成申请、预约、报名、下单或咨询等主动作。
5. 后台能够处理。
6. 用户能够看到状态反馈。

第二优先级：

- 板块内的完整业务流程。
- 更多服务扩展。
- 推荐、排序、标签、筛选等增强能力。

第三优先级：

- 视觉细节优化。
- 个性化推荐。
- 高级数据分析。
- 复杂运营配置。

## 八、状态定义

所有板块统一使用以下状态，不允许自行发明状态。

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚未正式启动 |
| 准备中 | 负责人、范围、资料正在补齐 |
| 开发中 | 板块功能正在开发 |
| 待联调 | 板块开发完成，等待平台集成 |
| 联调中 | 正在与服务广场或后台接口联调 |
| 待测试 | 联调完成，等待测试 |
| 测试中 | 正在测试 |
| 待验收 | 测试完成，等待负责人确认 |
| 已完成 | 已通过验收，可进入上线或发布流程 |
| 阻塞 | 存在影响推进的问题，必须进入问题池 |

## 九、变更规则

普通内容变更由板块负责人决定，例如标题、说明、活动内容、课程内容、商品上下架。

以下变更必须由 APP 总架构负责人确认：

- 服务广场主入口变更。
- 核心服务顺序变更。
- 板块层级变更。
- 底部导航变更。
- 跨多个板块的流程变更。
- 影响账号、权限、支付、消息、数据同步的公共规则变更。

以下变更必须同步平台集成负责人：

- 新增接口。
- 修改接口字段。
- 修改页面路由。
- 修改权限规则。
- 修改上线时间。
- 修改影响联调的业务流程。

## 十、验收标准

每个板块接入服务广场后，至少完成以下验收。

### 1. 页面验收

- 入口名称显示正确。
- 入口位置符合服务广场定版结构。
- 图标、按钮、文字不溢出。
- 移动端展示正常。

### 2. 跳转验收

- 点击入口后进入正确页面。
- 未登录、无权限、维护中、空数据等状态处理正确。
- 返回服务广场路径正常。

### 3. 接口验收

- 接口字段与文档一致。
- 正常数据、空数据、异常数据均可处理。
- 权限校验正确。

### 4. 业务验收

- 板块负责人确认业务内容正确。
- 平台集成负责人确认接入稳定。
- APP 总架构负责人确认没有破坏服务广场整体结构。

## 十一、执行要求

1. 各板块负责人先阅读本文档，再提交板块接入卡。
2. 平台集成负责人按接入卡建立接口与联调清单。
3. 每个板块进入下一阶段前必须提交 handoff 记录。
4. 所有阻塞进入问题池，不能只在群里口头处理。
5. 影响架构或公共规则的问题，必须形成决策记录。
6. 项目推进按主链路优先，先完成可运行闭环，再补充完整能力。

## 十二、当前结论

服务广场后续按“一个本地项目入口、一个总进度看板、一份接口清单、一个问题池、一套 handoff 交接机制、一套决策记录”推进。当前按 `docs/project-management/service-plaza/collaboration-tool-setup.md` 采用单人决策和 agent 协同。

各板块负责人按照本文档提交接入信息并推进交付。平台集成负责人按本文档组织联调。APP 总架构负责人按本文档维护架构边界和最终裁决。
