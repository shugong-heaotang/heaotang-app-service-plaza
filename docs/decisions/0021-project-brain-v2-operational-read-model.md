# Project Brain v2 采用失败关闭的经营只读模型

> 状态: 已采纳
> 日期: 2026-07-15
> 决策者: 项目最高负责人、Project Brain v2 项目负责人

## 背景

项目需要把治理状态和经营聚合用于日常管理及老板决策，但事实分散在不同 Owner 和系统中，并包含会员、健康、交易、客服等高敏感领域。

若 Project Brain 复制数据成为第二主库、允许 AI 回写、静默展示陈旧值或随代码合并自动上线，会破坏 v1 的单一权威和失败关闭边界，并扩大数据与运营风险。

## 决策

Project Brain v2 采用只读 operational read model：

- 每个事实绑定唯一 authority、Owner、freshness、quality、classification、permitted use 与证据；
- scheduler 仅通过只读适配器生成不可变快照；
- dashboard 只查询授权的只读视图；
- 缺失、过期、冲突、质量或权限失败时显示 `Unknown/No-Go`；
- 首期只允许项目治理事实和通过去标识审查的经营聚合；
- 禁止行级会员、健康、交易资金和客服数据；
- production route、snapshot、job、dashboard 和 export 默认关闭；
- 代码集成、测试环境验证和生产启用分别审批。

Project Brain v2 不成为业务主库，不拥有源系统写权，也不修改 Project Brain v1 的权威事实。

## 考虑的替代方案

| 方案 | 优点 | 缺点 | 为什么没选 |
| --- | --- | --- | --- |
| 建立 Brain 中央业务主库 | 查询统一、开发直观 | 形成第二权威、同步冲突、敏感数据爆炸半径大 | 违背 v1 单一权威和数据最小化 |
| Dashboard 实时直连各业务库 | 数据实时、少一层快照 | 权限难隔离、故障扩散、口径不可重放、存在误写风险 | 无法证明安全、稳定和可审计 |
| 只汇总人工填报表 | 初期简单、无需系统接口 | 陈旧、不可验证、责任和来源不清 | 不能支持可信经营决策 |
| 只读适配器、校验和不可变快照 | 权威清晰、可追溯、失败隔离、易回滚 | 增加来源映射、freshness 和运维治理成本 | 采用 |

## 后果

### 正面影响

- Brain 不夺取源系统所有权，决策可追溯到唯一事实与 Owner。
- 故障、陈旧和质量问题可见，不会被 AI 猜测或静默缓存掩盖。
- 读取、刷新、访问和发布均可审计。
- 敏感数据范围和生产爆炸半径受到限制。
- 快照、job、route 和 dashboard 可以分别禁用与回滚。
- 代码集成不会自动造成生产暴露。

### 已知风险和代价

- 每个指标都需要维护口径、Owner、freshness、质量、分级和用途，接入速度慢于直接连库。
- 快照不是绝对实时；老板必须看到数据截至时间和状态。
- 去标识聚合仍有小样本或组合重识别风险，需要阈值和持续审查。
- 多源系统的只读适配器和质量规则增加维护成本。
- Owner 不履责时，相关指标只能保持 `Unknown`。

### 需要后续关注的点

- M1 冻结事实合同、聚合阈值、来源映射和负例。
- M2 验证幂等刷新、并发互斥、告警、失败不覆盖和回滚。
- M3 验证服务端权限、解释性、禁止下钻和导出控制。
- M4 完成安全发布、禁用和回滚演练。
- 定期审计 authority、Owner、口径、freshness SLO 和数据分级是否漂移。
- 发生小样本或重识别风险时立即停用相关指标。

## 前提假设

- 源系统能够提供稳定、版本化、只读的事实或权威制品；若只能通过写操作取得数据，本决策必须重审。
- 业务 Owner 愿意承担口径、质量和 freshness 责任；Owner 长期缺失时对应指标保持 `Unknown`，而不是由 Brain 代填。
- 治理事实和经营聚合可以通过只读适配器获取；若业务必须实时执行跨系统事务，本模型不适用于该场景。
- 聚合能够通过最小群体阈值和重识别评估；若不能，相关指标不得进入 Brain。
- 生产平台能够提供独立开关、最小权限和审计；若无法隔离写权限，生产启用保持 `No-Go`。
- 老板和运营人员接受显式 `Unknown/No-Go`，不要求系统用推断填补证据缺口。

## 重审触发

出现以下任一情况时必须停止下游并新建 ADR，不得原地弱化本决策：

- 多权威冲突无法通过 Owner 治理解决；
- 提出行级敏感数据接入需求；
- 提出对源系统写回、自动审批或自动改状态需求；
- 监管、隐私或数据跨境规则变化；
- freshness 无法满足获批决策场景；
- 发生重识别或敏感数据暴露事件；
- 审计链断裂；
- 生产权限无法与写权限隔离；
- 不可变快照无法满足恢复要求；
- v1 权威范围或失败关闭语义发生正式变更。
