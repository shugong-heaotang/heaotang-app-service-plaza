# AI 开发使用单一强制治理入口

> 状态: 已采纳
> 日期: 2026-07-10
> 决策者: 项目负责人、平台集成负责人

## 背景

项目已经积累 ADR、管理制度、接口规范和验收台账，但新 Agent 可能只看到当前目录或旧 README，无法发现全部约束。后端 README 甚至曾描述与运行代码不同的未来技术栈，导致“规范存在但执行者没读到”。

## 决策

以 APP 系统根 README 第 0 节为唯一必读顺序，根 `AGENTS.md` 为 Agent 强制入口，后端仓库 README/AGENTS 只指向同一治理基线并陈述当前事实。开发前运行 preflight 校验必读文件和指纹；每份实现记录必须声明 `governance_inputs`，否则门禁失败。

## 考虑的替代方案

| 方案 | 优点 | 缺点 | 为什么没选 |
| --- | --- | --- | --- |
| 依靠 Agent 搜索全部文档 | 无维护成本 | 搜索不保证发现和理解 | 不可靠 |
| 每份文档复制全部规定 | 就近可读 | 多份副本快速漂移 | 不采用 |
| 单入口索引权威文档 | 可发现且避免重复 | 入口必须持续维护 | 采用 |

## 后果

### 正面影响

- 新 Agent 第一轮即可获得需求、规则、依赖、历史问题和当前状态。
- 后续实现可以证明采用了哪一版治理输入。

### 已知风险和代价

- README 第 0 节和 AGENTS 必须在新增治理类别时同步更新。

### 需要后续关注的点

- 连续检查后续三个业务切片是否都提交 governance_inputs。
- 工作区迁移时更新跨仓库治理基线路径。

## 前提假设

- 编程 Agent 会读取适用的 `AGENTS.md`；若某工具不支持，需要把 preflight 接入其 CI 或任务模板。
- 权威文件路径保持稳定；若重组目录，需要先更新入口和所有实现记录。
