# ADR 0018：大小项目执行同一套递归治理

- 状态：Accepted
- 日期：2026-07-10

## 背景

把板块视为平台中的一个功能，会让板块负责人缺少独立入口、依赖、计划、证据和交接；平台负责人代做业务又会形成单点瓶颈。项目负责人要求“大项目与小项目遵循同一套项目规则”，并以短检查点替代完工后一次性验收。

## 决策

1. 每个板块和重要切片都是独立子项目，必须具有 README、Owner、任务通知、接口、两层依赖、工作项、分支/工作树、检查单、考试、实施记录、测试证据和 Handoff。
2. 父项目负责人负责下达边界与接口、批准公共依赖、阶段抽查和最终集成；子项目负责人独立完成业务实现，不由父项目负责人代做。
3. 子项目拆为 2–4 小时或一个最小可测试成果的检查点。每个检查点先提交证据并通过门禁，再进入下一个检查点。
4. 检查点失败必须修复根因，不允许把缺陷积累到整个项目结束后统一处理。
5. 子项目不得修改父项目受保护接口；需要公共变更时提交变更请求，由平台集成负责人实现或合并。

## 后果

平台可以并行管理多个独立板块，问题在较小爆炸半径内暴露；代价是每个子项目需要维护一套精简但完整的项目证据。
