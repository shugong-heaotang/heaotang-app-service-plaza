# ADR 0015：Agent 独立工作与受控集成

- 状态：Accepted
- 日期：2026-07-10

## 背景

多个 Agent 在同一脏工作区连续或并行修改时，后来的 Agent 无法可靠区分用户修改、前序成果和自己的变更。仅靠阅读文档无法阻止覆盖、回退或重新实现，最终会形成难以验证的“代码石山”。

## 决策

1. 每个工作项必须登记唯一 ID、所有者、角色、基线提交、分支、工作树和允许修改范围。
2. 并行工作项默认使用独立 Git 分支和独立工作树；同一工作树同一时刻只能有一个活动工作项。
3. 活动工作项的修改范围不得重叠。平台契约、基础设施、治理规则和公共接口属于受保护范围，只能由平台集成负责人修改和合并。
4. 开工时必须检查工作树现状并确认基线；发现未归属的未提交变更时停止编辑并完成交接，禁止覆盖、清理或猜测其意图。
5. 完成时必须提交实现记录、变更范围、测试证据和 Handoff；集成负责人按依赖顺序逐项合并。冲突必须回到契约和所有权判断，禁止自动选择一方覆盖。
6. 当前历史共享脏工作区作为一次性迁移例外，如实登记并由平台集成负责人收口；例外不得复制到新工作项。

## 后果

并行开发多出工作树创建和集成步骤，但静默覆盖变为可见的范围冲突或合并冲突，前序成果可以沿基线追溯和恢复。
