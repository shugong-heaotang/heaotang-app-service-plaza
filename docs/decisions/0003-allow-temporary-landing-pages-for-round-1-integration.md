# 决策 0003：第一轮联调允许使用临时承接页

## 状态

已接受

## 日期

2026-07-09

## 背景

服务广场布局和三大核心服务入口已经定版。当前项目进入第一阶段推进，目标是尽快打通服务广场主链路，而不是等待所有板块正式页面、后台能力和完整业务流程全部完成后再联调。

如果三大核心服务必须等正式页面完全完成后才能开始联调，平台集成负责人无法提前验证路由、权限、登录状态、空状态、异常状态和返回路径，第一阶段主链路会被拖慢。

## 决策

第一轮联调允许生命导航、俱乐部联盟、健康大管家先使用临时承接页。

临时承接页只用于第一轮联调和主链路验证，不能改变服务广场已定版的信息架构、入口名称、入口顺序和核心服务范围。

临时承接页必须满足以下要求：

1. 页面标题必须与服务广场入口名称一致。
2. 页面必须说明当前板块处于第一阶段联调状态。
3. 页面必须包含一个第一阶段主动作入口或模拟动作。
4. 页面必须支持登录、无权限、空状态、异常状态的展示或模拟。
5. 页面必须能返回服务广场。
6. 页面必须标记为临时承接页，后续由正式页面替换。

## 前提

- 服务广场主入口、核心服务顺序和页面结构已经定版。
- 第一阶段目标是打通主链路闭环，不是一次性完成所有板块完整能力。
- 三大核心服务正式页面可能存在不同开发进度。
- 平台集成需要提前验证统一路由、权限、状态处理和返回路径。

## 影响

- 第一轮联调可以在正式页面未全部完成前启动。
- 平台集成负责人可以提前发现路由、权限、状态处理和跳转问题。
- 各板块负责人仍需补齐正式页面、正式接口和完整业务规则。
- 临时承接页不能作为最终上线页面，除非另有正式决策确认。

## 约束

- 临时承接页只适用于第一轮联调。
- 临时承接页不能新增服务广场主入口。
- 临时承接页不能改变生命导航、俱乐部联盟、健康大管家的层级和顺序。
- 临时承接页必须在正式页面可用后替换。
- 替换正式页面前，必须完成 handoff 记录和阶段验收。
