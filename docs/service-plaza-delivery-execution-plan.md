# 服务广场后续推进执行方案

日期：2026-07-09

本文档用于明确服务广场架构定版后的实际推进方式。后续工作由 APP 总架构负责人牵头，平台集成负责人组织落地，各板块负责人按统一 handoff 机制协同交付。

## 一、推进目标

当前目标不是继续调整服务广场架构，而是在既定架构下尽快完成系统主链路闭环：

1. 服务广场入口可用。
2. 核心服务和常用服务可进入。
3. 各板块主页面可访问。
4. 用户可完成核心动作，例如申请、预约、报名、下单、咨询或查看状态。
5. 后台或管理端可处理对应事项。
6. 用户能看到处理结果或状态反馈。

## 二、推进组织

采用“三层协作、统一交接”的推进方式。

| 角色 | 主要责任 | 核心产出 |
| --- | --- | --- |
| APP 总架构负责人 | 控制架构边界、主链路、跨板块规则和最终裁决 | 架构决策记录、验收结论、风险裁决 |
| 平台集成负责人 | 组织接口、路由、权限、联调、发布和问题关闭 | 接口清单、联调清单、发布检查表 |
| 各板块负责人 | 负责本板块内容、流程、页面、数据和验收 | 板块接入卡、handoff 记录、验收确认 |

## 三、总体工作方法

后续所有工作按以下顺序推进：

1. APP 总架构负责人确认服务广场主链路和阶段目标。
2. 各板块负责人提交板块接入卡。
3. 平台集成负责人根据接入卡形成接口与联调清单。
4. 各板块按优先级开发和补齐内容。
5. 每个板块完成阶段任务后提交 handoff 记录。
6. 平台集成负责人组织联调，问题进入问题池。
7. 测试通过后进入阶段验收。
8. APP 总架构负责人确认是否可以进入下一阶段或上线准备。

## 四、当前第一阶段任务

第一阶段只追求主链路打通，不追求所有细节完整。

### 1. APP 总架构负责人本周动作

- 确认服务广场主入口不再变动。
- 确认第一阶段必须打通的板块。
- 确认每个板块负责人名单。
- 确认平台集成负责人对接范围。
- 对影响架构和公共规则的问题进行裁决。

### 2. 平台集成负责人本周动作

- 建立服务广场接口与联调清单。
- 收集各板块接入卡。
- 统一页面路由、权限规则和接口字段要求。
- 建立问题与阻塞池。
- 安排第一轮联调顺序。

### 3. 各板块负责人本周动作

- 阅读《服务广场协作与交付规范》。
- 提交本板块接入卡。
- 明确本板块第一阶段最小可交付范围。
- 提供页面、接口、测试账号、测试数据和验收标准。
- 在阶段完成时提交 handoff 记录。

## 五、板块推进优先级

第一批优先推进核心服务：

1. 生命导航
2. 俱乐部联盟
3. 健康大管家

第二批推进常用服务：

1. 活动广场
2. 人脉中心
3. 保障商城
4. 二手集市
5. AI
6. 学习广场

如某个核心服务短期无法完成完整能力，可以先交付最小可用入口，但必须说明未完成范围和后续补齐时间。

## 六、Handoff 执行要求

Handoff 是强制机制。每个板块从一个阶段进入下一个阶段前，必须提交交接记录。

### 1. 需求交给开发

必须交付：

- 板块接入卡
- 页面说明
- 业务流程
- 权限规则
- 验收标准

### 2. 开发交给联调

必须交付：

- 页面路由
- 接口文档
- 测试账号
- 测试数据
- 已知问题
- 联调通过标准

### 3. 联调交给测试

必须交付：

- 测试范围
- 主流程测试路径
- 异常场景
- 不测试范围
- 当前风险
- 验收负责人

### 4. 测试交给上线准备

必须交付：

- 上线内容
- 影响范围
- 回滚方案
- 上线后验证项
- 最终确认人

没有 handoff 记录的板块，不进入下一阶段。

## 七、固定沟通机制

### 1. 每日推进会

参与人：APP 总架构负责人、平台集成负责人、各板块负责人。

时间：每天一次，15 分钟内。

每个板块只汇报三项：

```text
昨天完成：
今天计划：
当前阻塞：
```

### 2. 每周联调会

主持人：平台集成负责人。

重点处理：

- 接口是否定义完成。
- 路由和权限是否一致。
- 联调阻塞是否有人负责。
- 哪些问题需要架构负责人裁决。

### 3. 每周架构裁决会

主持人：APP 总架构负责人。

只处理：

- 架构边界问题。
- 主入口调整问题。
- 跨板块公共能力。
- 影响上线的重大风险。

## 八、问题升级规则

普通问题由板块负责人自行解决。

涉及接口、路由、权限、联调的问题，升级给平台集成负责人。

涉及架构边界、公共规则、板块冲突、上线取舍的问题，升级给 APP 总架构负责人。

超过一个工作日未解决且影响主链路的问题，必须进入问题池并标记为阻塞。

## 九、统一产出物

后续推进过程中，必须维护以下文件或看板：

| 产出物 | 负责人 | 用途 |
| --- | --- | --- |
| 总进度看板 | APP 总架构负责人 | 查看全局进度和风险 |
| Agent 协同配置清单 | APP 总架构负责人、平台集成负责人 | 明确单人决策、agent 协同、本地台账和 Handoff 入口 |
| 接口与联调清单 | 平台集成负责人 | 管理接口、路由、权限、联调状态 |
| 问题与阻塞池 | 平台集成负责人 | 跟踪阻塞和责任人 |
| 板块接入卡 | 各板块负责人 | 提交板块接入信息 |
| Handoff 记录 | 各板块负责人 | 阶段交接凭证 |
| 架构决策记录 | APP 总架构负责人 | 记录重大决定和裁决 |

## 十、执行口径

从现在开始，服务广场按以下口径推进：

服务广场由 APP 总架构负责人统一推动。平台集成负责人负责组织落地和联调。各板块负责人按照统一规范提交接入卡、更新进度、处理本板块问题，并在每个阶段通过 handoff 机制完成交接。当前项目只有项目负责人一人参与，因此所有状态更新以本地项目台账为准，agent 协同配置见 `docs/project-management/service-plaza/collaboration-tool-setup.md`。

所有板块优先完成主链路闭环。凡是影响服务广场架构、主入口、跨板块规则和上线节奏的问题，由 APP 总架构负责人统一裁决。
