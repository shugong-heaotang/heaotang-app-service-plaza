# 活动板块 V3.0 M0 需求合同说明

## 业务闭环

真实需求 → AI 在全部有权查看的活动中检索并解释主题及人群价值 → 用户自主报名 → 现场自然交流或经双方同意引荐 → 合作/标准交易进入受控系统 → 会后履约与成果沉淀 → 俱乐部持续承接。

## 不可变规则

1. 活动有且只有一个负责主办俱乐部；会员发布必须先形成提案并经俱乐部审批。
2. AI 输出是可解释、可关闭、带时间戳和不确定性的建议或草稿，任何外部动作都需人确认。
3. 会员等级只能来自平台正式字段；模型推测不能用于身份、人数或会员等级展示。
4. 小样本及组合标签可能反向识别时隐藏精确人数；具体人员展示和联系方式交换分别受授权与双方同意约束。
5. 活动商城引用既有可售商品，不复制商品、库存、价格或支付事实来源；商业推广必须标识。
6. 订单保存活动、俱乐部、商品、展示位置和来源；同一订单只能归因一次，退款和履约必须回写。
7. 重试必须幂等，不能造成重复活动、邀请、订单、扣款或消息。

## 当前隔离的待决策项

需求书第15章的10项决策在 M0 均标记为 `provisional`。它们不会被假定为已解决，也不授权 M1：会员提案默认权、L1-L3升级、平台复审、T1范围、退款分账模块、成果防刷、归档期限、收益/责任/IP、高风险准入、AI授权文本与保存期限。

逐条验收与负面用例见 `contracts/modules/activity/v3/requirements.v3.json`，依赖 readiness 见 `internal-dependencies.v1.json`。
