# `mall.api.v1` 契约冻结提案 M0-CP1

## 边界

服务广场只导航到商城，不代理商城业务。既有资源族暂保留为候选：`/api/mall/*`、`/api/admin/mall/*`、`/api/assurance-mall/*`、`/api/clubs/{clubId}/mall/*`；M0 不确认每个历史端点已经实现。

## 统一信封

成功响应：

```json
{"ok":true,"data":{},"meta":{"request_id":"req_...","correlation_id":"cor_...","contract_version":"mall.api.v1"}}
```

失败响应：

```json
{"ok":false,"error":{"code":"MALL_STABLE_CODE","message":"安全的用户提示","details":null},"meta":{"request_id":"req_...","correlation_id":"cor_...","contract_version":"mall.api.v1"}}
```

服务端生成或验证 `X-Request-ID`，通过 `X-Correlation-ID` 串联入口、订单、支付、履约和售后。日志不得记录凭据、完整支付信息或敏感会员内容。

## 权限

- 浏览能力是否允许匿名由平台会签决定；订单、账户、预约、核销、售后和后台动作必须认证。
- 权限同时校验 scope、资源归属、商城/俱乐部边界和商家归属。
- 不声明系统中不存在的 scope；M0 先冻结能力语义，具体 scope 名称待平台真实授权源会签。

## 幂等

创建订单、支付回调、退款、服务核销、权益回滚、提现及关键审核必须携带合法 `Idempotency-Key` 或具有等效数据库原子唯一约束。同键同载荷返回首次结果，同键异载荷稳定冲突，并发只产生一个业务结果。

## 审计

写操作记录 actor、resource、action、result、reason、request/correlation ID、幂等键摘要和时间。AI 风险建议与人工决定分开记录，AI 不自动处罚、扣保证金或改变权益。

## 配置失败关闭

价格、佣金、比例、保证金、有效期、退款窗口、库存政策和功能开关使用类型化版本配置。金额使用整数最小货币单位和币种；订单绑定配置版本快照。必需配置缺失时拒绝收费或关键动作，不使用猜测默认值。关键配置由不同人员录入和审核。

## 版本兼容

- v1 默认只允许向后兼容新增可选字段和新错误码。
- 删除、重命名、收紧语义或改变金额/状态含义属于破坏性变化，必须升主版本、记录 ADR、提供迁移窗口和回归证据。
- mock、文档或本地测试通过不代表真实环境可用。

## M1 前必须继续冻结的领域事实

商品责任主体、库存一致性、订单和支付状态机、回调验签、退款/对账、服务核销、保障账户权益生成与回滚。支付安全、资金状态机、回调验签和对账专项未 Go 前不得上线。
