# 健康大管家 R2-C1 双渠道统一档案合同冻结

## 结论

R2-C1 只冻结离线、合成、不可执行合同。本人自助与大益健康馆协助建档必须复用同一平台会员身份和同一主健康档案；渠道、门店或协助人员都不能成为档案所有人，也不能创建第二份主档案。

## 双渠道共同门禁

两条路径都要求会员本人完成身份确认、授权和候选资料最终确认。健康馆工作人员只能发起协助会话、协助录入或上传，并逐项留下门店、人员、来源、时间、授权版本和会员确认状态；未确认资料只能停留在 `candidate`。

当前没有正式代理规则，因此无法由本人操作的情形保持 `proxy_onboarding` No-Go。该局部 Pending 不阻塞合成合同、负例和独立验收。

## 数据与审计边界

- 每项资料都要有来源类型、来源引用、操作者、角色、时间、确认状态和来源版本。
- 会员自述、健康管理记录、专业签署记录和医疗机构电子病历必须分类，不得混称。
- 纠错采用追加版本并保留原始内容、来源和审计；撤回授权停止未来访问，不删除既有审计链。
- 协助建档默认医生关系为 `not_established`，不得自动形成诊疗关系。

## AI 边界

AI 仅可整理合成资料、识别缺失、生成待会员确认的候选和解释来源；不得验证真实身份、授权、最终确认、删除原始资料、诊断、开药、改药、冒充医生或关闭专业/紧急风险。

## 验收范围

`test_health_r2_dual_channel_record.py` 提供 Schema、基线和 14 个负例门禁，覆盖重复主档案、工作人员代授权、未确认提升、来源缺失、记录混称、删除原始、授权未版本化、审计缺字段、自动医生关系、AI 越权、代理建档、真实数据授权和敏感模式。
