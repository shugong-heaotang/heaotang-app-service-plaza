## 首页信息架构

第一屏优先级固定为：风险提醒和当前健康行动优先于商城、广告或机构排名。

七个一级入口：我的健康档案、我的健康计划、找医生与专业帮助、疑难病例协同、健康学习、健康俱乐部、大益健康馆服务。

两条路径：

1. 纵向健康服务：建档 → 测评 → 计划 → 日常行动 → 风险转人工 → 找医生/MDT → 结果回到会员记录。
2. 横向健康参与：健康馆 → 健康学习 → 健康俱乐部 → 共学/活动/互助 → 会员自主反馈 → 经确认后健康管理复盘。

关键页面状态包括未登录、待授权、就绪、资料不完整、待会员确认、专业风险转人工和失败关闭。

## 权威边界

| 权威方 | 拥有的数据 | 只允许展示的摘要 | 禁止行为 |
| --- | --- | --- | --- |
| 健康大管家 | 健康档案、授权、健康计划 | 当前目标、已授权推荐上下文 | 接收未确认的跨模块写入 |
| 学习广场 | 资源、路径、进度 | 正在学、完成状态、资源引用 | 健康大管家复制进度或自动写回 |
| 俱乐部联盟 | 成员关系、活动、反馈 | 可见卡片、本人加入状态 | 无独立授权读取完整健康档案 |
| 医生集团/平台目录 | 资质核验、专业标签、可接诊状态 | 核验、专科、服务能力 | AI创建资质或付费改变安全排序 |
| 合规医疗机构 | 正式诊疗、电子病历 | 经授权结果、转介状态 | 健康馆冒充医疗机构形成病历 |

## 跨模块协议

唯一允许模式：

1. 展示最小摘要：需要会员授权、数据最小化、权威来源和来源版本。
2. 跳转权威模块：权威模块保留写入所有权，不共享数据库写入。
3. 会员确认回传：必须有会员明确确认、来源、版本、责任人，并由目标模块复核后记录。

学习完成、俱乐部活动或反馈均不得自动进入健康档案；健康大管家不得直接改变学习进度或俱乐部成员关系。

## AI 与专业边界

AI可做资料整理、缺失识别、使用已专业审核规则进行风险提示、从已核验候选池匹配并解释原因、为人工复核准备摘要。

AI不得诊断、开药、改药、冒充医生、承诺疗效、关闭专业或紧急风险、推荐未核验人员，或因商业费用改变医疗优先级。

## Pending 与 does-not-block

隐私法律、医疗质量、平台安全、健康馆运营四类会签均保持 `pending-with-owner` 且 `executable=false`。

这些 Pending 阻塞 R2 实现、共享运行时、真实数据、医疗、收费、部署和生产；不阻塞 R1 合同一致性、合成验收设计，以及 R1 独立验收后准备 R2 任务书。
