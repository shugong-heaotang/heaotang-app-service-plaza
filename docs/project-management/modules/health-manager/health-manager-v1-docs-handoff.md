#### MVP 最小状态机

1. **开始健康管理**：未开始 → 已阅读服务边界 → 已完成最小授权 → 安全筛查中 → 可继续 / 待补资料 / 转人工 / 紧急引导；紧急引导不得继续生成普通计划。
2. **健康计划**：AI 草案 → 待管理师审核 → 待补资料或待专业审核 → 待会员确认 → 已生效 → 已暂停 / 被新版本替代 / 已结束；未经会员确认不得生效。
3. **健康任务**：待开始 → 进行中 → 完成 / 部分完成 / 延后 / 无法完成 / 因不适暂停 → 按规则进入人工处理；过期和无法完成不等于会员失败。
4. **风险事件**：已发现 → 初步分级 → 提醒 / 关注 / 专业 / 紧急 → 处理中 → 待复核 → 继续观察 / 升级 / 人工关闭；AI 不得独立关闭专业和紧急风险。
5. **人工沟通**：待发送 / 待回复 → 已送达 → 已回复 / 超时 / 无法联系 → 已处理或升级；“已发送”不能冒充“已解决”。
6. **授权**：待确认 → 生效 / 部分授权 → 变更 / 撤回 / 到期；撤回立即阻止新的非必要访问，历史记录按正式保留规则处理。

#### 必须失败关闭的情况

- 无法确认本人身份或有效服务关系；
- 必需授权缺失、过期或已撤回；
- 安全筛查资料不足却试图生成确定性结论；
- AI 输出与医生或管理师已签署意见冲突；
- 风险规则、人员资质、模板版本或关键责任人配置缺失；
- 管理师超过安全容量且没有可用接管人；
- 专业意见来源、时间、资质或适用范围不可验证；
- 幂等依据缺失导致可能重复创建计划、风险或服务记录。

| MVP-A002 资料不足 | 关键筛查资料选择“不知道”或缺失 | 不生成确定性报告；明确待补资料或转人工 | 规则版本、缺失字段和分流记录 |
| MVP-A003 紧急风险 | 筛查或对话触发紧急规则 | 普通计划流程立即中止，显示紧急引导并创建人工处置记录 | 风险事件、提示版本、通知与人工接管证据 |
| MVP-A004 任务导致不适 | 会员在执行中选择“因不适暂停” | 任务暂停，不鼓励继续；按规则转人工或专业处理 | 任务状态、反馈原文、升级记录 |
| MVP-A005 连续无法执行 | 多次延后或无法完成 | 不惩罚会员；分析障碍并形成待确认调整草案 | 偏差摘要、Advance 草案和会员确认状态 |
| MVP-A006 AI 越权拦截 | AI 尝试给出诊断、药物调整或确定性预测 | 输出被安全边界拦截，保留合规解释和转人工入口 | 拦截类型、规则版本、脱敏审计记录 |
| MVP-A007 AI 不可用 | 模型超时、失败或返回不可解析内容 | 已确认计划、风险入口和联系人工仍可使用；不伪造 AI 建议 | 故障状态、降级界面和恢复记录 |
| MVP-A008 授权撤回 | 会员撤回可选或核心授权 | 新的非必要访问立即停止；显示影响范围和历史处理规则 | 授权版本、撤回时间和拒绝访问证据 |
| MVP-A009 越权访问 | 无服务关系管理师尝试读取会员资料 | 服务端拒绝且产生安全审计，不依赖前端隐藏 | 拒绝响应、actor、resource、reason 和审计事件 |
| MVP-A010 管理师超容量 | 管理师达到容量预警后继续分配 | 新分配失败关闭并进入调度；已有紧急风险不被丢弃 | 容量快照、拒绝原因和接管结果 |
| MVP-A011 模板或规则失效 | 计划模板过期、风险规则缺失或版本不可验证 | 禁止新计划生效，提示管理端修复，不使用宽松默认值 | 配置校验结果和失败关闭事件 |
| MVP-A012 重复提交 | 重复点击任务完成、计划确认或风险上报 | 产生一个业务结果，后续请求返回相同幂等结果 | idempotency key 与唯一业务 ID |
| MVP-A013 人工消息未送达 | 发送失败、会员未读或超时 | 不标记为已解决；按规则重试、换渠道或升级 | 发送状态、重试和超时处理记录 |
| MVP-A014 数据纠错 | 会员纠正 AI 提取或人工录入的错误资料 | 原始来源保留，当前事实更新，影响计划进入复核 | 前后版本、纠错人、原因和受影响对象 |
| MVP-A015 安全退出 | 会员暂停或退出试运行 | 普通任务停止，风险和必要提示妥善交接，说明数据处理 | 退出确认、任务处理和数据权利说明 |

#### 合成数据和试运行边界

- 开发、自动化、截图、日志和演示默认只使用合成数据；
- 合成数据必须覆盖成年本人、资料不足、慢病用药、过敏、行动不适和授权撤回，但不能复制真实会员资料；
- 核心会员试运行属于新的高风险阶段，需要独立知情同意、专业值班、人工容量、投诉和退出方案；
- 未通过合成数据的安全负例和恢复场景，不得进入核心会员试运行；
- 试运行结果只能证明所覆盖人群、周期和服务模型，不能外推临床效果或长期商业可行性。

#### 非功能验收底线

- AI 或消息通道故障不能阻断风险上报、查看已确认计划和联系人工；
- 授权撤回、风险升级、计划生效和关键审计需要强一致或明确的补偿状态；
- 所有写入操作必须定义幂等依据、重试策略和重复结果；
- 敏感字段不进入普通日志，导出、查看和人工接管均需最小权限；
- 老年会员常用路径支持清晰文字、足够点击区域、保存继续和错误恢复；
- 正式延迟、可用性、人工响应和恢复指标保持 Pending，不能以未裁决数字冒充验收通过。

#### PRD-C3 Go 条件

上述 15 个主场景、权限负例、AI 禁止动作、合成数据边界和故障降级必须都有负责人、输入、预期状态、可自动化部分、人工验收部分和证据保存位置。只描述“应安全”“应友好”而没有可观察结果，不构成 C3 Go。

#### 决策记录规则

- `Accepted` 必须记录决定人、时间、依据、适用版本和被替代条件；
- `Pending` 必须记录阻塞原因、需要的证据、责任人和最迟检查点，不能只写“以后再定”；
- `Rejected` 必须说明被拒方案及原因，避免后续以新名称重复引入；
- 任一专业、安全、隐私或运营决策不得由 AI 自行从 Pending 改为 Accepted；
- 价格、容量、响应时间、积分和有效期等变量不能因为 PRD 需要示例而变成硬编码承诺。

#### PRD-C4 Go / No-Go

PRD-C4 只有在以下条件全部满足时为 Go：

1. 首批会员、MVP 承诺、8+5 页面、PDCAR 主路径和明确非目标已经冻结；
2. 医疗安全、AI 禁止动作、风险升级、身份授权和数据权利不存在影响首期的未处置阻断项；
3. 所有 MVP-A001—A015 场景都有可验证责任和证据方案；
4. 人工容量、值班、故障替代、投诉、退出和回退具备可执行方案；
5. 两层依赖为 development Go，任何 Pending 能力均不被首期路径隐式依赖；
6. 联合评审人对本人责任域签署 Accepted，且没有同人审核关键安全配置；
7. PRD Handoff 清楚列出剩余 Pending、非目标和后续独立业务切片。

出现以下任一情况即为 No-Go：

- 用“90 天”要求删除最小授权、风险升级、人工接管、审计或失败关闭；
- 把疾病诊疗、药物调整、健康结果保证或寿命预测包装成 Lite 功能；
- 没有管理师安全容量、值班或超容量替代方案；
- 使用真实健康数据弥补合成测试不足；
- 未裁决的价格、积分、健康年龄或家庭授权进入首期必经路径；
- 页面和流程已经冻结，但对象状态、异常和验收仍无法形成唯一解释；
- 平台未正式派发独立业务工作项便要求开始代码、接口或 Schema。

PRD-C4 可得出“文档 Go、业务实现仍 No-Go”；文档评审通过本身不会自动授权开发。

### 明确非目标

- 不建设完整 53 页面蓝图；
- 不建设家庭健康空间、俱乐部深度联动、健康馆加盟或区域运营；
- 不建设完整医生工作台、多服务商调度、分润和企业后台；
- 不把示例价格、管理师工时、工作量权重或容量假设固化为正式配置；
- 不允许 AI 诊断、开药、改变用药、独立关闭专业风险或扩大授权；
- 不使用真实会员健康数据完成开发和测试。

### 建议阶段检查点

- PRD-C0：正式工作项、专用工作树、当前检查单、100 分考试和两层依赖；
- PRD-C1：会员承诺、首批对象、八个会员页面和五个管理页面冻结；
- PRD-C2：PDCAR 主流程、对象、状态、权限和 AI/人工责任冻结；
- PRD-C3：风险、隐私、异常、非功能和可测验收冻结；
- PRD-C4：产品、专业、法律、安全、运营与平台联合评审，形成 Accepted/Pending 决策表；
- PRD-C5：PRD Handoff，通过后再申请第一个业务实现切片。
