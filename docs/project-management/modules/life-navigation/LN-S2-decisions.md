# 生命导航 LN-S2 P0 决策包

## D-LN-S2-001：维度注册表与旧 yun 策略

- status：`Pending`
- decision_owner：项目负责人
- prepared_by：生命导航二负责人
- prepared_date：2026-07-12
- implementation_allowed：false

### 推荐

维度使用稳定 ID 与独立版本，展示文案不作为主键；目录和 selector 只消费经项目负责人 Accepted 且 active/executable 的注册项。配置缺失、读取失败、空或非法时失败关闭。旧 `yun` 在历史中原样保留稳定 ID，在裁决前不得映射到任何新维度。

### 待项目负责人确定

- 首版稳定维度集合、中文 label 和排序；
- 每个维度的启停、authority 与版本兼容政策；
- 旧 `yun` 的迁移、只读兼容或废弃方式；
- 历史未知维度的最终用户文案。

### 禁止替代方案

- 继续在前端固定 `yun`；
- 由前端拉取宽目录后本地筛选；
- 配置异常时使用代码默认目录；
- 用中文 label 或 sort order 充当稳定主键；
- 在 Pending 时把候选维度设为 active/executable。

### 前提与证伪

- 前提：申请与历史能够持久化 `dimension_id + dimension_version`；若现有数据模型无法稳定保存二者，必须复审。
- 前提：一个申请只引用一个主维度；若未来允许多维度/层级组合，必须升版并重新设计 selector。
- 前提：服务端能够原子读取同一版本注册表并验证 active/executable；若多实例出现版本漂移，需要引入配置版本一致性门禁。
- 前提：旧 `yun` 数据可被识别且不需要伪造新 label；若历史量或业务含义证明需要批量迁移，必须提交迁移/回滚/抽样验证方案。

### 复审触发

任一前提被证伪；新增多值或层级分类；维度语义承担评分/预测/专业结论；发生未知维度串流；配置无法失败关闭；或需要破坏性更名时，重新提交项目负责人裁决并评估主版本升级。

### 兼容与迁移

P0 Accepted 后只能向后兼容新增注册项；稳定 ID 不得就地改义。破坏性变化需新主版本、迁移窗口、历史显示兼容和回滚证据。当前不执行迁移。
