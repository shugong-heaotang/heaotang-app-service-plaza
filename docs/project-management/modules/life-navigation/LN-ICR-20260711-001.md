## 变更事实

- 当前契约：
  - GET 本人历史固定为 `GET /api/v1/life-nav/records?limit=<1..30>`。
  - POST 同键同载荷重放为 HTTP 200，并带 `Idempotency-Replayed: true`。
  - 模块必须复用平台共享 API adapter，不得自行复制认证、信封、重试或幂等实现。
- 运行时事实：
  - 后端 `ListRecords` 对 `limit=1..100` 均直接接受，仅在 `limit<=0` 或 `limit>100` 时回退 30，与固定 1..30 范围不一致。
  - 后端正确设置 `Idempotency-Replayed: true`，但前端共享 `apiRequest` 只返回 `payload.data`，`businessApiAdapter.execute` 也不返回 HTTP 状态或响应头，模块无法区分首次创建与重放。
- 具体缺口及复现：
  - 代码事实：`service.go` 中 `if limit <= 0 || limit > 100 { limit = 30 }`；请求 `limit=31` 至 `100` 不会被拒绝或夹紧到 30。
  - 代码事实：`plugin.go` 在重放时设置响应头后调用 `response.OK`；`apiClient.ts` 最终仅 `return payload.data`。
  - 现有 Go 测试证明首次 201、重放 200+响应头、同键异载荷 409；前端 adapter 测试只验证 data、错误码和幂等键，不提供响应元数据。
- 为什么模块内适配不能解决：
  - 模块可以把自己的 GET limit 限制为 1..30，但不能消除公共运行接口对其他消费者的契约漂移。
  - 模块无法在不绕过共享 adapter 的情况下读取重放响应头；自行 `fetch` 会复制受保护平台能力并破坏统一边界。
- 是否阻塞当前检查点：阻塞 `LN-M1-001` 进入 M2 的 Go。接口事实已查清，但重放反馈设计需平台裁决；不得带着未决公共边界进入实现。

## 影响分析

- 受影响消费者：生命导航申请页面、后续复用 `businessApiAdapter` 且需要响应元数据的写操作；所有直接调用 GET records 的客户端。
- 向后兼容性：
  - 模块继续只发送 1..30 无破坏性影响；若后端把 31..100 从接受改为拒绝或夹紧，可能影响未登记消费者，需先扫描。
  - 给共享 adapter 增加可选元数据返回方式应保持现有 `execute(): Promise<T>` 行为不变，采用兼容扩展；或在响应 `data` 增加明确 `replayed` 字段并保留响应头。
- 权限、隐私、幂等和数据影响：不改变共享 JWT、本人 SQL 过滤或幂等事务；必须避免把 Authorization 或用户 ID 交给模块管理。
- 迁移与回滚：兼容扩展保留现有调用；新能力仅由声明需要元数据的操作启用。后端 limit 修正若发现既有消费者，先给迁移窗口并保留可回滚版本。
- 必需测试：
  - 共享 adapter 对首次 201 与重放 200 的元数据区分，同时保持严格信封、请求 ID、取消和同键重试。
  - GET limit 的 0、1、30、31、100、101 边界契约测试。
  - 本人归属、跨用户不可见、同键同载荷、异载荷、处理中和并发限额回归。

## 建议与裁决

- 申请方案：兼容扩展。建议平台为共享 adapter 提供不破坏现有 `execute` 的响应元数据读取能力，或兼容扩展 POST data 返回 `replayed`；同时裁决 GET limit 以固定契约 1..30 为准并扫描 31..100 的既有消费者。
- 平台决定：接受兼容扩展。保留现有 `execute(): Promise<T>` 行为，平台新增可选 `{ data, meta }` 响应能力；`meta` 至少包含 `status`、`requestId`、`idempotencyReplayed`。GET records 的 `limit` 固定为 1..30，越界安全默认 30；平台扫描未发现登记的 `limit>30` 消费者。补充用户 A 不可见用户 B 的负向测试。
- 决定理由：模块需要重放元数据但不得绕过共享 adapter；兼容扩展可保持现有消费者不变。将 limit 收敛到已冻结的 1..30 可关闭契约漂移，且当前无登记的 >30 消费者。显式跨用户负向测试用于把 SQL 事实升级为可复跑的权限证据。
- ADR 或契约版本：保持 v1，采用向后兼容扩展并补充契约与回归测试；若实施发现未登记消费者或破坏性影响，平台工作项必须重新评估版本与迁移。
- 允许实施范围：平台独立工作项已完成共享 adapter、后端 limit 边界及相关平台/Go 测试；生命导航二负责人未修改 `app/src/infrastructure/`、后端或公共契约。
