## 1. 一句话定位

**学习广场是和奥堂体系的独立通用学习平台与学习事实源**：它不属于生命导航、不专属于俱乐部、不归 Nova；Nova 学习助手只是它的一个内部应用，Nova AI Engine 是平台共享能力。所有学习进度、完成事实、证书与成长证据由学习广场唯一持有，外部项目只能通过版本化事件消费投影，不能反向修改学习事实。

## 4. 五个共享地基（本方案的核心新增）

以下五条是整个体系的共享能力，先冻结成标准，再谈功能：

### 4.1 统一资源身份（Resource ID）

- 文章、课程、书、笔记、直播、回放、考试统一挂在 `resource` 模型下。
- 每个资源必须有：`resource_id`（平台唯一）、`resource_type`、`version`、`source_refs`（来源/版权依据）、`owner_id`、`visibility_scope`、`status`、`review_trace`。
- 跨模块引用一律使用 `resource_id + version`，禁止用标题/路径/副本引用，杜绝重复对象和失效链接。

### 4.2 学习事实源（Learning Fact Source）

- 报名、课时完成、进度、完成事实、证书、学习时长只由学习广场写。
- 外部系统（生命导航、健康馆、会员成长档案、数据中台）只能读取投影或消费事件。
- 商城退款导致权益关闭时，学习广场执行「停止新访问 + 学习记录保留但不对外投影」的规则；是否删除记录由产品决策，不由商城直接删表。

### 4.3 权限 Scope（服务端双校验）

- 可见性四档：`public`（公开引流）、`member`（登录可见）、`club`（俱乐部可见）、`private`（仅授权人）。
- 后端每个读接口必须做 `owner + scope` 双校验；前端隐藏只是体验，不是权限。
- 课程发布后用户端才可见；草稿仅作者/审核员可见；越权一律 404/403，不得泄露存在性。

### 4.4 审核治理（Review Governance）

- 默认流程：AI 初审 → 人工终审；`ai_review_enabled` 与 `human_review_enabled` 可独立开关。
- 开关变更 = 关键配置，必须版本化 + 双人审批（maker-checker）。
- 双关模式：仅获授权发布者可直发，但仍强制记录审计字段：发布者、来源引用、版权依据、内容版本、发布时间、变更日志、下架状态、复核痕迹。
- 任何发布路径（课程/知识/读书/笔记/证书模板）都保留完整审计，不允许绕过。

### 4.5 成长事件（Growth Event）

- 事件类型固定：`learning.growth.recorded.v1`。
- 必填字段：`event_id`、`idempotency_key`、`user_id`、`learning_object_id`、`recorded_at`、`evidence_refs`、`event_version`。
- 写入策略：`emit-versioned-event`，绝不直接写消费者数据库。
- 消费者：生命导航、俱乐部联盟、会员成长档案（后续加数据中台、健康馆投影）。
- 语义：幂等事件 + 消费者确认 + 可重放；重复完成只产生一次事件。

## 5. 首期范围（P0/P1）与后置（P2+）

### 5.1 P0 最小闭环（必须先立住的主链）

提交课程 → 审核 → 发布 → Nova 推荐 → 开始学习 → 记录进度 → 完成 → 生成成长事件 → 外部投影确认。

P0 必须交付：

- 课程：分类（层级）、课程→章节→课时、草稿/发布状态机；
- 学习：报名（幂等）、课时完成（幂等）、进度自动重算、我的课程；
- 统一资源 ID 与 scope 权限；
- 审核链（AI 初审 + 人工终审，可开关）；
- 成长事件端口（learning-growth.events.v1）与幂等消费；
- 基础搜索与基础排序（按发布时间/学习人数，不引入复杂算法）。

### 5.2 P1 首批扩展

- 读书：`book/note` 资源类型，经典书单、21 天读书计划、心得、打卡（不做完整阅读器）；
- 证书：仅建证书模板与证书模型（不提供手动发证主流程）；发放由考试通过自动发证驱动，考试接入后启用（见决策 8）；我的证书/核验入口随自动发证一起提供；
- Nova 学习助手：基于用户可见资源问答，必须带引用（≥1），无引用时回答「资料不足」；禁止代报名/代完成/代发证；
- 健康馆只读摘要：「正在学 / 最近完成 / 推荐学习」由学习广场只读投影接口提供；
- 俱乐部共学入口：学习组织权 ≠ 内容所有权；共学讨论、进度分享为 P1 后段。

### 5.3 P2+（预留，不阻塞 P0/P1）

- 考试认证（题库/试卷/成绩/考试通过自动发证——证书发放主路径）、直播与会议（第三方 SDK、费用俱乐部自担）、知识商品交易（order-payment 端口）、学习路径完整化（大医疗法路径）。

### 5.4 后置/不做（展示类优化）

热门排行算法、搜索联想、学习热力图、学习周报、能力雷达图、排行榜等一律后置；首版只做列表、基础搜索、进度展示。不做任何真实付费/支付流程（P2 前）。

## 8. 状态机与幂等（服务端强制）

- 课程：`draft → submitted → in_review → published → archived | takedown`；只有 `in_review` 的审核通过才能进入 `published`。
- 学习：`not_started → in_progress → completed`；支持 `cancelled`（退出）与恢复；`completed` 后可重看但不再重复产生完成事件。
- 幂等键：报名（resource_id+user_id 唯一）、课时完成（lesson_id+user_id 唯一）、成长事件（idempotency_key 唯一）。
- 非法转换（如未报名直接完成、草稿被推荐）必须被后端拒绝，并返回稳定错误码。

## 9. 跨模块关系（本方案确定的边界）

| 模块 | 关系 | 规则 |

| 生命导航 | 外部关联 | 接收成长目标/维度 → 推荐学习资源；消费成长事件投影，不写学习事实 |

## 10. 验收口径（可执行、可演示）

### 10.1 最小闭环测试服旅程（P0 Go 条件）

1. 管理员提交课程 → 走审核 → 发布；
2. 登录用户在课程列表可见该课程，未登录用户按 scope 规则可见/不可见；
3. 用户报名（重复报名幂等）→ 完成课时 → 进度自动到 100% → 课程完成；
4. 系统生成一条成长事件，外部消费者（先以生命导航/健康馆投影为样例）确认收到；
5. Nova 对已发布课程提问返回带引用的答案；对用户不可见资源提问不返回内容。

### 10.2 独立负面用例（fixtures）

- 未报名用户直接完成课时 → 拒绝；
- 草稿/未审核课程出现在公开列表或 Nova 推荐 → 拒绝；
- 非俱乐部成员读取 club 资源 → 404/403；
- Nova 无引用回答 → 返回「资料不足」；
- 同一完成事件重复提交 → 只产生一条事件；
- 双关审核模式下直发仍必须留下全部审计字段。

### 10.3 进度状态口径

- 标准、实现、验证、测试服 UAT、产品进度分开报告；
- 页面打开 / HTTP 200 / 合同通过 / 文档齐全不单独构成完成证据；以测试服完整旅程 + 独立验收为准。

## 12. 需要张总/负责人拍板的决策点

> 确认状态：2026-08-10 张总确认——第 1-7 条按推荐执行；第 8 条调整为「考试通过自动发证，不做手动发证主流程」。

| # | 决策点 | 本方案默认建议 |
|---|---|---|
| 1 | 学习广场定位 | 独立通用学习平台（吸收 ADR 0001） |
| 2 | 命名统一 | 全部叫「学习广场」 |
| 3 | 知识商品目录归属 | 学习广场拥有知识类目录，商城只做订单/支付/售后 |
| 4 | 审核开关策略 | AI 初审+人工终审可独立开关，双人审批，双关直发留审计 |
| 5 | 付费课程 | P2 前不做真实付费，价格字段只展示 |
| 6 | 退款后学习记录 | 默认保留记录但不对外投影（是否删除另行决策） |
| 7 | 直播费用 | 第三方 SDK，费用俱乐部自担，平台只做入口与回放 |
| 8 | 证书权益 | 考试通过自动发证（主路径）；不做手动发证主流程；证书模板/模型随考试接入一起建设 |

---

### 12.1 各决策点分析意见（2026-08-10，供张总参考后决策）

**1. 学习广场定位**

证据：需求 v1.0 已写「通用学习平台」；M0 任务单 7-13 先写「生命导航学习执行层」，同日 ADR 0001 / v3.0 又改为「独立通用学习平台」；健康需求补充明确「读书、课程、知识学习统一归学习广场」，健康管理师认证也要复用学习广场底层能力——这两条都是独立平台才成立的用例。

分析：选「执行层」会形成循环依赖（生命导航推荐→学习广场学习→再回写生命导航），Nova 归属、目录所有权、商城边界全部跟着模糊；选「独立平台」只是多付出路由/应用注册表/事件端口的建设成本，而这些 M0 已经合同化。风险主要是初期成本，不是方向。

建议：**独立通用学习平台**。

**2. 命名统一**

证据：页面目录叫课程广场、业务点清单叫学习成长中心、原型叫和奥堂商学院、服务清单和 M0 叫学习广场，同一个板块四个名字。

分析：命名现在改成本最低，越晚越贵。服务清单 manifest、M0、需求文档都已倾向「学习广场」，选它做总名；课程广场做课程入口别名、商学院做商业课程专区入口，文档里一次对齐。

建议：**统一为「学习广场」**。

**3. 知识商品目录归属**

证据：商城基础框架思路原文「学习广场已有课程类能力时，商城 1.0 不重复做复杂课程体系」；商城横向关系梳理也写「商城只负责购买、订单、支付和售后入口，学习广场负责课程交付、学习记录和学习评价」。

分析：商城文档自己已经倾向不重复建目录。若商城再建一套课程目录，会出现两个事实源，权益开通/退款/学习记录三处对不上。正确模型是：商城 SKU 只引用学习广场的 resource_id，支付成功→开通权益（order-payment 端口），退款→回收访问权。

建议：**知识类目录归学习广场，商城只做交易**。

**4. 审核开关策略**

证据：v3.0 合同已冻结「AI 初审+人工终审可独立开关、开关变更双人审批、双关直发留审计」；体系缺口清单第 10 条点名审核开关缺运行时治理。

分析：健康相关内容有合规要求（健康需求补充明确 AI 不能替代医生判断），所以不能一刀切。建议按内容类型分级：健康医疗类强制人工终审；普通课程可双开默认人工终审、授权后仅 AI；双关只给平台运营授权发布者，且必须留完整审计。

建议：**采用 v3.0 开关模型 + 健康类强制人工终审**。

**5. 付费课程**

证据：开发文档 P1 明确「不做课程付费」；order-payment 端口仍是 provisional；真实支付涉及资金安全、退款、分账、税务，属于不可逆外部动作。

分析：首期把免费/公益课作为种子内容（正好对应公益课体系 LEARN-06），价格字段只展示，不接真实支付；把支付冻结成端口，等课程闭环跑通再单独授权接入。这样既不卡主链，也不碰资金风险。

建议：**P2 前不做真实付费，免费/公益课先行**。

**6. 退款后学习记录**

证据：商城横向关系梳理两处写「课程商品退款后，学习记录不保留」；v3.0 又说学习事实由学习广场唯一持有。两条规则直接冲突。

分析：学习记录是已经发生的事实（审计、纠纷、消费者权益都需要留痕），访问权才是可以被回收的权益。建议把两者分开：保留记录，回收访问权，未完成课程权益关闭，已获证书标记 revoked，且记录不对外投影。是否物理删除，留作合规决策，不默认删。

建议：**保留记录但不投影，回收访问权；证书 revoked**。

**7. 直播费用**

证据：需求 v1.0 与开发文档一致写「第三方 SDK、费用俱乐部自担、平台只做入口和回放」。

分析：自研音视频成本高、周期长、运维重，不符合平台当前阶段；第三方 SDK 成熟且俱乐部作为学习组织者承担教学场景费用合理。风险在接入前评估第三方合规（内容安全、回放留存、未成年人），P3 再做，不阻塞 P0/P1。

建议：**第三方 SDK + 俱乐部自担 + 平台只做编排与回放**。

**8. 证书时机**

证据：需求 v1.0 写「证书提前到 P2，不依赖考试，可手动发证；考试 P4」；旧课程模型有 RequireExam/AutoIssueCert 但当前插件未实现。

分析：手动发证的使用量少、维护成本性价比低；直接把证书挂在考试通过上自动发证更符合实际（健康管理师认证本身就是课程+考试+证书的组合）。代价是证书随考试系统一起上线，不构成 P1 独立能力，也不阻塞 P0 课程闭环。证书状态机仍需包含 revoked/expired/verify，并与退款规则（决策点 6）联动。

决策（2026-08-10 张总确认）：**考试通过自动发证（主路径），不做手动发证主流程**。
