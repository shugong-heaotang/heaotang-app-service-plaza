# 服务广场启动确认行动项跟踪表

本文件用于跟踪第一轮联调启动确认产生的行动项。启动确认结论只有进入本表，并明确处理角色、截止时间、目标文件和关闭标准，才算进入执行。

## 一、使用规则

1. 启动确认结束后 2 小时内，文档 Agent 必须把行动项登记到本文件。
2. 每个行动项必须有唯一编号、处理角色、截止时间、目标文件和关闭标准。
3. P0 行动项到期未完成，必须进入 `blocker-escalation-decision-log.md`。
4. 行动项关闭后，必须回写目标台账，不能只在本文件标记完成。
5. 行动项影响 Go / Partial Go / No-Go 时，必须同步更新 `phase-gate-status.md` 和 `first-integration-go-checklist.md`。

## 三、关闭检查

| 检查项 | 要求 |
| --- | --- |
| 是否有处理角色 | 不能写“待定”或“大家” |
| 是否有截止时间 | 必须明确到日期或确认后小时数 |
| 是否有目标文件 | 必须能回写到项目台账 |
| 是否有关闭标准 | 必须能判断完成或未完成 |
| 是否有证据编号 | 影响门禁时必须登记证据编号 |
| 是否影响门禁 | 影响时必须同步更新门禁文件 |
| 是否需要裁决 | 到期未完成时登记阻塞裁决台账 |

## 四、行动项状态

统一使用以下状态：

| 状态 | 含义 |
| --- | --- |
| 待执行 | 确认已产生行动项，但尚未开始 |
| 处理中 | Agent 正在补齐 |
| 信息不完整 | 已有部分信息，但不能关闭 |
| 已关闭 | 已回写目标文件并满足关闭标准 |
| 已裁决 | 已进入 `blocker-escalation-decision-log.md` 并由项目负责人裁决 |
| 已取消 | 经项目负责人裁决不再执行 |
