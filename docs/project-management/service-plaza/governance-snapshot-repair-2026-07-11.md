# 治理考试快照字节漂移根因修复

- 发现时间：2026-07-11
- 发现门禁：`scripts/validate_governance_exams.py`
- 影响范围：并行板块通知书审计任务的 R1、R2、R3 三份考试
- 当前结论：旧试卷保留但失效隔离；必须以新 R4 检查单和考试重新认证

## 现象与证据

三份考试都记录了当时检查单的 SHA-256，但当前 Git `HEAD` 中对应检查单的原始字节哈希不同。逐文件确认：工作树与 Git blob 一致、均为 UTF-8 无 BOM/LF；Git 历史中不存在考试记录的旧哈希，因此不能把旧试卷继续冒充为可验证快照，也不能直接改写旧试卷的哈希。

## 根因

`New-AgentDevelopmentChecklist.ps1` 在 Windows PowerShell 5.1 中直接写入 `ConvertTo-Json` 的平台换行；检查单随后通过逐项编辑完成，考试按提交前工作树原始字节计算哈希。Git 对 JSON 执行 LF 规范化后，提交中的字节与考试时字节不同。旧工作树字节没有作为独立制品保存，因此旧哈希无法从 Git 恢复。

## 修复

1. 三份失效考试原样移动到 `contracts/foundation/invalidated-snapshots/parallel-notices-audit-fix/`，不删除、不改写为通过。
2. 使用当前治理输入为原通知书审计任务建立 R4 检查单和 100 分考试，并把实施记录、审计报告和 Handoff 指向 R4。
3. 检查单生成器固定写入 UTF-8 无 BOM/LF/单一末尾换行。
4. 考试生成器在计算哈希前强制拒绝 BOM、CRLF、非法 UTF-8 或缺少末尾换行的检查单，确保考试哈希经过 Git 文本规范化后保持不变。
5. 暂存时 Git 又准确预警当前验证码门禁 R1-R3 检查单会发生 CRLF 到 LF 转换；对应中间检查单与试卷一并移入 `invalidated-snapshots/test-otp-capacity-gate/`，最终授权升级为规范 LF 的 R5。

旧试卷隔离不是删除历史，也不是放宽门禁；它明确宣告原快照不能证明完整性，并以新认证替代其授权作用。

## 验证结果

- 三份隔离试卷与修复前 Git `HEAD` 中对应文件逐字节相同，SHA-256 分别保持 `6b4020df...`、`ba85c053...`、`b6f165fa...`。
- 新生成的两份 R4 检查单均为 UTF-8 无 BOM、LF、单一末尾换行。
- 负向测试把 R4 检查单临时转换为 CRLF 后，考试生成器按预期拒绝并返回退出码 1；未生成试卷。
- 原通知书审计 R4 与当前验证码门禁最终 R5 均为 8/8、100 分。
- 开发检查单、治理考试、实现记录、协作范围、重复问题、服务广场契约、UTF-8、全部 PowerShell AST 与 `git diff --check` 总门禁通过。
