# 治理 current 快照自引用根因闭环

## 结论

2026-07-12，健康大管家 MVP-90 M0 与生命导航 LN-S2 P0/P1 连续触发同一模式：模块入口检查单和考试在开始时有效，但切片必须更新 `internal-dependencies.v1.json`，而该文件同时属于模块治理 overlay。成果更新后，入口检查单记录的 SHA 必然不再 current。

这不是模块业务缺陷，也不能通过修改旧检查单、忽略 SHA 或跳过最终考试解决。

## 根因链

1. 派发时把内部依赖图作为必读治理输入；
2. 同一派发又要求模块在本切片中更新该内部依赖图；
3. 派发只授权一份检查单、一次考试和一份实施记录；
4. 入口检查单完成后，合法成果使必读文件 SHA 改变；
5. 旧快照不可改写，而模块又没有第二组精确证据路径，最终收口被治理路径本身阻塞。

## 系统性修复

- 保留入口检查单和考试为不可修改历史证据；
- 为健康 M0 和生命导航 LN-S2 分别新增精确 R2 checklist/exam 路径；健康另新增 R2 IR，生命导航现有 IR 在最终收口时引用 R2；
- 最终成果和内部依赖图完成后，模块必须重新全文读取当前治理输入、重新参加随机考试并取得 100 分；
- 以后派发审查必须识别“既是治理 overlay、又是切片输出”的可变文件，并在正式通知和协作登记中预先授权最终 current 快照，不再等到收口阶段临时扩权。

## 不允许的替代方案

- 修改已完成的入口检查单或考试；
- 把旧 SHA 声称为 current；
- 从 overlay 删除内部依赖以换取表面通过；
- 跳过最终 current 验证；
- 复制临时目录或削弱 validator。

## 验收

平台登记 `RI-CURRENT-CHECKLIST-MUTABLE-OVERLAY`；协作登记只增加精确 R2 文件，不扩大任何业务、前端、后端、环境或部署权限。两个模块收到集成后的 registry 基线后，分别生成 R2 current 检查单、100 分考试和最终实施记录，再申请平台验收。
