# 平台联调条件确认记录模板

本文件用于补齐第一轮真实联调所需的平台条件。当前项目按单人决策和 Agent 协同推进，不使用外部回执链路；平台信息只有形成事实证据后，才能回写到门禁和联调台账。

## 一、确认范围

| 类别 | 证据编号 | 必填内容 | 当前状态 |
| --- | --- | --- | --- |
| 环境 | EV-PLAT-001 | 联调环境名称、访问地址、服务广场入口 | 待补齐 |
| 路由 | EV-PLAT-001 | 三大核心服务正式路由或临时承接页路由 | 待补齐 |
| 权限 | EV-PLAT-002 | 未登录、普通会员、无权限、管理或审核权限规则 | 待补齐 |
| 账号 | EV-PLAT-003 | 普通会员、无权限、管理或审核账号获取方式 | 待补齐 |
| 数据 | EV-PLAT-004 | 正常、空状态、异常数据 | 待补齐 |
| 返回路径 | EV-PLAT-005 | 各核心服务返回服务广场路径和异常返回规则 | 待补齐 |

## 三、证据关闭口径

| P0 编号 | 证据编号 | 关闭前必须具备的事实字段 | 不允许作为关闭证据的内容 |
| --- | --- | --- | --- |
| P0-PLAT-001 | EV-PLAT-001 | 环境地址、服务广场入口、三大核心服务正式路由或临时承接页路由 | 只有建议路由、只有口头判断 |
| P0-PLAT-002 | EV-PLAT-002 | 未登录、普通会员、无权限、管理或审核权限规则和预期页面状态 | 只写“按平台默认权限” |
| P0-PLAT-003 | EV-PLAT-003 | 测试账号类型、获取方式、所属环境、安全说明 | 记录真实密码、只写“账号后补” |
| P0-PLAT-004 | EV-PLAT-004 | 每个核心服务的正常、空状态、异常数据来源或模拟方式 | 只有一个正常样例、无异常状态 |
| P0-PLAT-005 | EV-PLAT-005 | 三个核心服务返回服务广场方式、异常或无权限后的返回规则 | 只说明浏览器返回键 |

## 四、回写文件

平台确认记录补齐后，按以下顺序回写：

1. `routing-and-temporary-page-spec.md`：回写 EV-PLAT-001 和 EV-PLAT-005。
2. `test-accounts-and-data.md`：回写 EV-PLAT-002、EV-PLAT-003 和 EV-PLAT-004。
3. `integration-checklist.md`：同步平台准备项和联调前检查状态。
4. `p0-evidence-closure-queue.md`：只在事实字段完整后，把对应 P0 状态从“待补齐”改为“证据已形成，待门禁复核”。
5. `first-integration-go-checklist.md`：由审计 Agent 复核后再决定是否维持 No-Go、改为 Partial Go 或 Go。

## 五、当前结论

截至 2026-07-09，平台侧 EV-PLAT-001 至 EV-PLAT-005 仅建立字段和关闭口径，尚未形成事实证据。首次真实联调继续保持 No-Go。
