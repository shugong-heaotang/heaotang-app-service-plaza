## 四、可接收证据标准

| 证据类型 | 可接受内容 | 不可接受内容 |
| --- | --- | --- |
| 主动作确认 | 项目负责人或板块 Agent 明确采用或替换主动作，并有证据编号或记录位置 | 只有推荐默认项 |
| 页面方案 | 明确正式页面、临时承接页或其他唯一方案，并能回写路由或页面位置 | 正式页和临时页同时保留为待定 |
| 权限规则 | 登录、会员权限、无权限状态和页面预期状态清楚 | 只有“需要登录”等原则描述 |
| 后台处理 | 提交后处理人、处理路径、审核或状态反馈清楚 | 只有“后续处理” |
| 测试数据 | 正常、空状态、异常数据有来源、mock、fixture 或临时页模拟方式 | 只有测试计划，没有数据来源 |
| 验收责任 | 验收责任 Agent、通过标准和不通过回退动作明确 | 只有“待验收” |

## 五、回写规则

1. 板块事实补齐后，先回写 `core-service-confirmation-reply-template.md`。
2. 同步回写 `module-intake-cards.md` 和 `core-service-main-action-confirmation.md`。
3. 涉及路由、账号、测试数据和返回路径的字段必须同步给平台侧台账，但不替代 FE-PLAT。
4. 三项板块事实具备真实证据后，才能填写 `fact-evidence-submission-packet.md` 的板块事实提交包。
5. 提交后由 `fact-evidence-intake-review.md` 判断 FE-MOD 是否进入待复核或退回补充。
6. 审计复核只能写入 `fact-evidence-review-run-log.md` 的 FR-MOD，不得直接解除首次真实联调 No-Go。

## 六、当前禁止动作

1. 不把推荐主动作当作已确认主动作。
2. 不把空确认模板当作板块事实。
3. 不把板块页面方案替代平台路由、账号、数据和返回路径事实。
4. 不在 FE-MOD 未复核前触发 FE-HO 质量复核。
5. 不触发 FE-GATE、FE-ACC 或首次真实联调。
