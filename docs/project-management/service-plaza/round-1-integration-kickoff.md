# 服务广场第一轮联调启动包

日期：2026-07-09

本文件用于定义第一轮联调的边界和启动条件。当前项目只有项目负责人一人参与，启动包不再作为多人会议材料，而是作为项目负责人和 Agent 接续推进的统一依据。

## 一、联调目标

第一轮联调只验证服务广场主链路和三大核心服务的最小闭环：

1. 服务广场主页面可以进入。
2. 三大核心服务入口可以点击。
3. 每个核心服务都有明确目标页面或临时承接页。
4. 每个核心服务至少定义一个第一阶段主动作。
5. 平台能处理登录、权限、空状态、异常状态和返回路径。
6. 每个核心服务完成一次可复核的 Handoff。

## 二、联调范围

| 板块 | 是否进入第一轮 | 联调重点 | 不在本轮处理 |
| --- | --- | --- | --- |
| 服务广场总入口 | 是 | 页面可访问、入口可见、跳转可用 | 首页、发现、我的完整设计 |
| 生命导航 | 是 | 入口跳转、主动作、状态反馈 | 完整十维度内容体系 |
| 俱乐部联盟 | 是 | 入口跳转、俱乐部分类、管理中心关系 | 完整俱乐部运营后台 |
| 健康大管家 | 是 | 入口跳转、健康服务主动作、后台处理路径 | 完整健康档案和复杂医疗服务 |
| 活动广场 | 否 | 暂不进入第一轮 | 第二批接入 |
| 人脉中心 | 否 | 暂不进入第一轮 | 第二批接入 |
| 保障商城 | 否 | 暂不进入第一轮 | 支付、订单、售后第二批处理 |
| 二手集市 | 否 | 暂不进入第一轮 | 审核、交易第二批处理 |
| AI | 否 | 暂不进入第一轮 | 页面级 AI 能力边界另行裁决 |
| 学习广场 | 否 | 暂不进入第一轮 | 第二批接入 |

## 三、启动前置条件

| 序号 | 前置条件 | 责任角色 | 状态 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 总架构推进职责写入责任台账 | 文档 Agent | 已回写 | RPLY-001 已确认 |
| 2 | 平台联调条件确认 | 平台 Agent | 待补齐 | 路由、账号、数据、权限、返回路径缺失 |
| 3 | 三大核心服务责任边界确认 | 板块 Agent | 待补齐 | 每个板块一份确认记录 |
| 4 | 三大核心服务接入卡提交 | 板块 Agent | 待补齐 | 使用 `module-intake-cards.md` |
| 5 | 路由和临时承接页确认 | 平台 Agent | 待补齐 | ADR 0003 允许无正式页面时先用临时承接页 |
| 6 | 测试账号和测试数据准备 | 平台 Agent | 待补齐 | 至少覆盖正常、无权限、空状态、异常状态 |
| 7 | Handoff 记录建立并复核 | 板块 Agent、审计 Agent | 待补齐 | 未通过质量复核前保持 No-Go |

## 四、当前门禁

| 阶段 | 结论 | 原因 |
| --- | --- | --- |
| 启动确认 | Conditional Go | 管理台账和模板已建立，但真实证据仍需补齐 |
| 首次真实联调 | No-Go | 平台条件、三大核心服务确认、Handoff 质量复核未完成 |
| 第一阶段验收 | No-Go | 无真实联调记录、问题关闭和验收证据 |
