# 服务广场剩余 8% 人类可执行行动包

日期：2026-07-10

本文件把当前服务广场项目管理台账中所有待补齐待提交待确认的管理字段，压缩为人类可直接执行的下一步动作。它不增加新的管理文件，只定义：谁、什么时候、做什么、填哪里。

当前整体完成度约 92%。剩余 8% 是真实工程事实的形成和回填，不再需要新的管理台账。

---

## 总览：三个缺口

- 平台事实（环境/路由/权限/账号/数据/返回路径）：约5%，人类必做，Agent 可回填
- 板块确认（三大核心服务主动作/页面/权限/后台/验收）：约2%，人类必做
- Handoff 提交与质量复核：约1%，人类确认后 Agent 自动执行

---

## 动作一：补齐平台事实（人类必做，约5%）

1. 确认联调或测试环境 -- 告诉项目负责人环境名称和可访问地址 -- platform-fact-submission-worksheet.md FE-PLAT-001
2. 确认服务广场总入口 -- 告诉前端工程或 App 中服务广场入口位置 -- 同上
3. 确认三个核心服务的路由或临时页 -- 每个服务给一个可访问路由或临时承接页实现位置 -- 同上
4. 确认权限规则 -- 写清楚未登录/普通会员/无权限/管理账号各能看到什么 -- FE-PLAT-002
5. 提供测试账号 -- 给项目负责人账号类型和获取方式（不写真实密码） -- FE-PLAT-003
6. 提供测试数据 -- 每个服务的正常/空状态/异常数据来源或模拟方式 -- FE-PLAT-004
7. 确认返回路径 -- 每个服务如何返回服务广场、无权限或异常时怎么办 -- FE-PLAT-005

人类完成后平台 Agent 把字段回填到 fact-evidence-submission-packet.md，进入 FR-PLAT 复核。

---

## 动作二：确认三大核心服务主动作（人类必做，约2%）

生命导航：主动作=提交导航申请，页面方案=正式页或临时承接页，权限要求=仅登录会员，后台处理=提交到审核到反馈

俱乐部联盟：主动作=申请加入俱乐部，页面方案=正式页或临时承接页，权限要求=登录会员申请+管理员审核，管理中心边界=主板块附属，审核规则=管理员审核

健康大管家：主动作=提交健康咨询，页面方案=正式页或临时承接页，权限要求=仅登录会员，后台处理=提交到分配咨询师到回复

人类确认后板块 Agent 把结果回填到 core-service-main-action-confirmation.md，同步到 round-1-handoff-forms.md。

---

## 动作三：提交 Handoff 并复核（Agent 代劳，人类只需同意事实）

当动作一和动作二都完成后，Agent 自动执行：

1. 板块 Agent 把三大模块确认结果填入 round-1-handoff-forms.md SP-H002/003/004
2. 板块 Agent 在 handoff-fact-submission-worksheet.md 填写 FE-HO-001/002/003 字段
3. 平台 Agent 在 handoff-log.md 登记接收记录
4. 审计 Agent 在 handoff-quality-review.md 复核通过/退回
5. 审计 Agent 更新 fact-evidence-intake-review.md FE-HO 为待复核
6. 审计 Agent 更新 fact-evidence-review-run-log.md FR-HO 为按事实复核
7. 审计 Agent 更新 p0-evidence-execution-log.md P0-HO 为可关闭
8. 所有 Agent 更新 first-integration-go-checklist.md 判断 Partial Go / No-Go

## 七、并行审计发现

本节记录三个并行子代理对服务广场项目剩余缺口的审计结果。

### 7.1 Handoff 表单审计

- 三个 SP-H 表单字段完整，每个都有结构化字段和关闭条件
- 14-15 个必填字段全部为空
- 阶段标准与复核表不一致：阶段标准只要求 5 个必填字段，复核表实际检查 11-13 个
- EV-HO-001 关闭条件有笔误：要求后台处理但 SP-H002 无此字段
- 核心阻塞因子：责任边界、主动作确认、页面方案均为空

### 7.2 模块确认卡片审计

- 三个模块结构完整
- 50+ 个字段全部为待补齐
- 字段缺口：module-intake-cards.md 没有无权限状态字段
- 核心阻塞因子：主动作确认（MA-Q001/002/003）阻塞所有后置动作

### 7.3 联调准备度审计

- 剩余至少 28 个独立事项（6 PRE-Q + 9 ACT + 13 P0）
- 必须人类做 5 项：裁决主动作、裁决临时承接页、提供测试账号、提供测试数据、升级裁决
- Agent 可代劳 13 项
- 隐式阻碍：启动确认从未真实进行
- 最短路径：H-01 到 H-02 到 A-05 到 A-06 到 A-08 到 A-09 到 A-12 到 Go/Partial Go

### 7.4 修复建议

- 在 module-intake-cards.md 的三个模块卡片中追加无权限状态字段
- 在 handoff-quality-review.md 中将阶段标准从 5 项修正为 11 项
- 将 EV-HO-001 关闭条件中的后台处理改为验收责任

### 7.5 后续接手阅读顺序

1. 先读 START-HERE.md 明确当前 No-Go 结论
2. 再读本文件明确人类必做事项
