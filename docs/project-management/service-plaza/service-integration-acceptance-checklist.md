# 服务广场接入验收清单

使用方法：每个服务复制一份清单，逐项填写证据。`M` 为强制项，`C` 为按场景适用项。任何强制项失败或未验证时，不得把服务状态改为 `active`。

## G0 申请与责任

- [ ] `M` 接入申请编号、服务 ID、版本和目标环境完整。
- [ ] `M` 业务、技术、安全/隐私和运行支持联系人已指定。
- [ ] `M` 平台集成负责人已确认变更分级。
- [ ] `C` 主版本、重大架构变更或标准例外已取得 APP 总架构负责人批准。

证据：

## G1 清单与目录契约

- [ ] `M` 清单通过 `contracts/service-plaza/service-manifest.schema.json` 校验。
- [ ] `M` `service_id` 唯一且未复用于其他服务。
- [ ] `M` 名称、摘要、类别、排序、状态、能力、提供方和业务 API 版本准确。
- [ ] `M` 目录接口和单服务接口返回标准成功/失败结构。
- [ ] `M` 未完成服务使用 `planned` 或 `preview`，没有伪装成可用状态。

证据（命令、响应或报告）：

## G2 导航、认证与权限

- [ ] `M` 内部路由以 `/services/` 开头，或外部入口为白名单 HTTPS/已审核小程序。
- [ ] `M` `/services` 返回路径有效，浏览器前进、后退和刷新行为正确。
- [ ] `M` 登录、未登录、无权限、空状态、异常、维护和下线状态均有验证。
- [ ] `M` 权限使用最小 Scope，401 与 403 语义正确。
- [ ] `C` 外部登录使用 OIDC 授权码模式和 PKCE，回调地址严格匹配。
- [ ] `M` URL 中无 JWT、验证码、手机号、健康信息或其他个人数据。

证据：

## G3 业务 API 契约

- [ ] `M` API 路径和业务版本明确，字段命名符合标准。
- [ ] `M` 200/201、400、401、403、404、429 及适用的 5xx 行为经过契约测试。
- [ ] `M` 失败响应包含稳定机器码和用户可读错误，不泄漏堆栈或内部秘密。
- [ ] `M` 用户归属从认证会话取得，请求体不能覆盖 `user_id`。
- [ ] `M` 重复提交的幂等或冲突策略已声明并验证。
- [ ] `M` 超时、重试和限流不会造成重复写入或无限请求。

证据：

## G4 用户主链路与可观测性

- [ ] `M` 从服务广场进入、完成主动作、收到反馈、返回服务广场全链路通过。
- [ ] `M` 桌面和目标移动端视口完成 UAT，无关键内容不可达。
- [ ] `M` 关键导航、授权失败、提交结果和异常有可追溯事件或日志。
- [ ] `M` 监控、告警、健康检查和运行支持升级路径可用。
- [ ] `M` 日志使用关联 ID，且不记录凭据或个人敏感正文。

证据：

## G5 数据、安全与合规

- [ ] `M` 数据最小化、保存期限、删除机制和用户授权已说明。
- [ ] `M` 传输使用 TLS，秘密通过安全配置注入，不进入代码、URL、日志和材料。
- [ ] `M` 认证、授权、输入校验、越权、重放和开放重定向完成风险验证。
- [ ] `C` 敏感健康、支付、未成年人或跨境数据取得专项验收。
- [ ] `C` 外部合作方域名、证书、隐私政策和数据处理责任完成审核。
- [ ] `M` 所有高危和中危发现已关闭并提供复测证据。

证据：

## G6 环境、测试与回滚

- [ ] `M` 自动化测试、契约测试和文本/编码门禁通过。
- [ ] `M` 测试环境部署版本与待验收制品可追溯。
- [ ] `M` 测试账号和数据通过安全渠道提供，测试数据可清理。
- [ ] `M` 部署、健康检查、回滚步骤和触发条件已验证。
- [ ] `M` 未通过跳过测试、弱化规则或临时绕行获得表面成功。

证据：

## G7 Handoff 与启用

- [ ] `M` Handoff 的提交人、接收人、范围、版本、环境和时间完整。
- [ ] `M` 未完成项、风险、依赖、Owner 和计划日期明确。
- [ ] `M` 板块业务验收与平台接入验收分别给出结论。
- [ ] `C` 安全/合规和重大变更审批结论已附证据。
- [ ] `M` 平台集成负责人确认所有强制项均为通过后，才把状态改为 `active`。

证据：
