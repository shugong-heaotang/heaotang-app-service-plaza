## 四、执行记录字段要求

每次第一阶段验收执行必须补齐以下字段；缺任一字段时，本记录只能作为未完成记录，不能作为 Go 证据。

| 字段 | 填写要求 | 缺失时处理 |
| --- | --- | --- |
| 执行时间 | 写明开始和结束时间 | 回到验收执行记录补齐 |
| 验收范围 | 写明整体或单板块，并列出板块名称 | 范围不明时保持 No-Go |
| 触发证据编号 | 引用 EV-001 至 EV-013 中的相关编号 | 回到证据登记 |
| 执行 Agent 和复核 Agent | 写明执行、验收、审计角色 | 回到执行责任确认 |
| 执行结果 | 写明实际结果，不能只写“待确认”或“计划完成” | 该项不得通过 |
| 未通过原因 | 对每个否项写明原因、阻塞级别和回退阶段 | 回到问题登记 |
| 新增问题编号 | 阻塞项同步到问题池或问题关闭表 | 回到问题关闭阶段 |
| 项目负责人裁决 | 写明裁决结果、依据和是否允许进入下一阶段 | 不形成最终结论 |

## 八、Go / No-Go 判定口径

| 判定 | 必须满足 | 本记录写法 |
| --- | --- | --- |
| Go | 全局验收项和进入范围内的核心服务验收项均通过；FE-GATE、FE-ACC、EV-011、EV-012、EV-013 均已形成并通过复核；项目负责人允许进入下一阶段 | `是否允许进入下一阶段：是`，最终状态写“通过” |
| Partial Go | 仅部分板块满足 Go，FE-GATE、对应板块 FE-ACC、未通过板块的阻塞原因、隔离边界和回退动作明确；项目负责人接受范围限制 | `是否允许进入下一阶段：是，仅限指定板块`，最终状态写“单板块通过” |
| No-Go | 任一触发证据缺失、FE-GATE 或 FE-ACC 未复核、主链路阻塞未关闭、Handoff 未完成、执行记录缺字段、项目负责人未裁决或裁决不通过 | `是否允许进入下一阶段：否`，最终状态写“不通过” |

截至当前状态，所有执行项仍为待执行或待补充，因此不得把本记录改写为 Go 或 Partial Go。
