# 服务广场公共基础设施建设计划 v1

总依赖关系、业务板块准入和后续并行顺序见 `../dependency-driven-master-plan-v1.md`。本文件只维护服务广场公共基础设施 F1 至 F8 的实施状态。

## 目标

在各板块大规模开发前，提供稳定的接入入口和公共运行底座。基础设施只解决跨板块共同问题，不提前猜测生命导航、俱乐部联盟、健康大管家等板块尚未冻结的业务功能。

## 建设顺序与完成定义

| 阶段 | 公共能力 | 必须交付的接口或组件 | 完成门禁 |
| --- | --- | --- | --- |
| F1 | 契约与目录 | `service-plaza.v1`、`service-plaza.action.v1`、公开 Schema、目录 API、动作 API | 20 项页面动作、9 项服务目录、前后端与公开 Schema 一致；契约测试通过 |
| F2 | 身份与会话 | 统一登录、JWT 会话、认证状态、外部 OIDC/PKCE 边界 | 未登录/过期/无权限具有统一机器错误码；外部服务不得接收平台 JWT |
| F3 | 统一 API SDK | 请求封装、超时、取消、错误对象、关联 ID、受控重试 | 业务适配器不直接重复拼接认证和错误解析；错误码不会丢失 |
| F4 | 动作执行器与权限 | 内部路由、平台命令、外部 HTTPS、服务变体、生命周期和 scope 门禁 | 未登记类型拒绝执行；规划/维护/下线动作不可误触发；权限失败可审计 |
| F5 | 写入可靠性 | `Idempotency-Key`、重复请求结果、请求校验、统一响应信封 | 生命导航、俱乐部申请、健康咨询重复提交不产生重复业务记录；并发测试通过 |
| F6 | 契约测试工具包 | Manifest/Action 校验、适配器测试夹具、接入方自检、兼容性门禁 | 新板块可在不修改平台代码的情况下完成本地自检；破坏性变更被 CI 拒绝 |
| F7 | 可观测性与配置 | request/correlation ID、结构化日志、动作埋点、健康/就绪、功能开关 | 一次用户动作可跨前后端追踪；开关变更可审计且有默认安全值 |
| F8 | 交付与恢复 | CI、测试环境发布、备份、回滚、部署证据 | 发布失败自动回滚；备份可恢复；常规发布不隐式轮换密钥 |

## 当前状态（2026-07-10）

- F1：已完成测试环境部署与现场验收。目录 9 项；动作 20 项且 ID 唯一；页面 20 个动作由目录驱动；公开 Schema 和基线清单可访问。
- F2：内部身份会话已完成并部署。v1 信封、稳定错误码、原子验证码消费、真实 `scopes` 和旧接口兼容均已验证；外部 OIDC/PKCE 仍待实现。
- F3：已完成并部署。统一 SDK 已覆盖严格 v1 信封、机器错误码、超时、取消、`X-Request-ID` 和受控重试；写请求禁止无幂等键重试。
- F4：内部动作权限已完成。生命周期、目标协议、平台命令/OIDC 处理器白名单、真实 `club:manage` 和权限审计事件已实现；外部 OIDC 执行器仍待完成。
- F5：已完成并部署。三项正式写入强制 `Idempotency-Key`，首次/重放/异载荷/非法键/并发和生命导航日限额均已通过测试环境或竞态测试。
- F6：已完成。Schema、CI、自检工具、统一业务 API 适配器模板和破坏性契约差异门禁均已通过自动化测试。
- F7：已完成内部底座并部署。动作事件严格绑定目录且拒绝额外敏感字段；功能开关默认关闭、失效安全关闭、管理员变更留审计；客户端最多 60 秒刷新开关。
- F8：已完成。备份已在隔离 Linux 目录真实恢复；部署后模拟门禁失败已自动恢复原二进制哈希并通过 `/ready`。演练中发现的非原子覆盖竞态已改为临时文件校验后原子替换。

## 板块并行开发准入

F1 至 F6 全部通过后，板块负责人可以独立开发业务功能。每个板块必须：

1. 提交服务 Manifest 和页面 Action，不直接改服务广场布局代码。
2. 只通过统一 API SDK 调用平台接口。
3. 使用统一身份、权限、错误和幂等规则。
4. 通过接入方自检、板块业务测试、安全门禁和测试环境 UAT。
5. 重大或破坏性变更按 ADR 0005 升级审批。

## 最近的执行队列

1. 分别冻结生命导航、俱乐部联盟、健康大管家的需求、非目标、数据责任和验收标准。
2. 冻结完成的板块按统一适配器模板独立开发、测试和接入。
3. 并行建立外部合作服务 OIDC/PKCE 专项实现与安全测试；它不阻塞纯内部板块，但阻塞任何外部服务转为 active。
