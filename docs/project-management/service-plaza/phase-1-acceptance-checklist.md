# 服务广场第一阶段验收清单

第一阶段验收目标：证明服务广场主链路已经打通，核心服务可以进入、可以产生用户动作、后台可以处理、用户可以看到状态反馈。

## 验收触发条件

第一阶段验收必须先满足以下触发条件。触发条件只决定是否可以开始验收，不等同于验收通过；缺任一项时，本清单保持 No-Go。

| 触发条件 | 验收前要求 | 证据编号 | 当前状态 |
| --- | --- | --- | --- |
| 联调门禁可转换 | 第一轮联调门禁为 Go，或明确 Partial Go 板块范围 | EV-001、EV-003 | 待补充 |
| 首次真实联调记录完整 | 联调范围、环境、通过项、失败项、问题编号齐全 | EV-003 | 待补充 |
| 主链路问题关闭或明确延期 | 阻塞项已关闭；延期项不阻塞第一阶段范围 | EV-004 | 待补充 |
| 联调给测试 Handoff 完成 | Handoff 表单、日志和质量复核可追溯 | EV-005 | 待补充 |
| 路由、权限、数据证据齐全 | 服务广场入口、核心入口、权限、空状态、异常状态有证据 | EV-006、EV-008、EV-009 | 待补充 |
| 验收执行记录可追溯 | 执行记录包含范围、Agent、证据编号、结果、回退动作和裁决 | EV-011、EV-012、EV-013 | 待补充 |

## 七、Go / No-Go 判定口径

| 判定 | 使用条件 | 本清单要求 |
| --- | --- | --- |
| Go | 所有触发条件、全局验收、进入范围内核心服务验收、Handoff、测试账号与数据均通过；EV-011、EV-012、EV-013 已形成 | 状态可写“通过”，并在执行记录中允许进入下一阶段 |
| Partial Go | 仅指定板块满足 Go，未通过板块隔离边界、阻塞原因和回退动作明确 | 状态只能写“单板块通过”，不得覆盖未进入验收板块 |
| No-Go | 触发条件缺失、证据待补充、阻塞问题未关闭、执行记录未产生或负责人未裁决 | 状态保持 No-Go，并登记缺失证据和回退动作 |

当前所有关键证据仍为待补充，第一阶段验收不得从 No-Go 改为 Go。

## 十、验收进入规则

进入第一阶段验收前，必须先按 `integration-to-acceptance-transition.md` 完成复核，并在 `acceptance-evidence-register.md` 登记证据。进入验收后，必须在 `phase-1-acceptance-run-record.md` 记录真实执行、证据编号、未通过项、回退动作和项目负责人裁决。没有联调记录、问题关闭结论、Handoff、验收证据编号和验收执行记录时，本清单保持 No-Go。
