# 服务广场确认补齐节奏表

本文件用于定义 P0 确认事项未补齐时的处理节奏。当前项目按单人决策和 agent 台账推进，不再以对外消息和等待多人回复作为主流程。OUT-001 补齐证据统一登记在 `out-001-followup-evidence-register.md`。

## 一、补齐原则

1. P0 确认事项必须有确认人、确认时间、确认结论和证据编号。
2. 超过本轮处理时间仍未补齐，由执行 Agent 登记补齐动作。
3. 再次未补齐，由审计 Agent 判断是否影响门禁。
4. 仍影响首次真实联调或验收时，提交项目负责人裁决。
5. 进入裁决处理后，必须登记到 `blocker-escalation-decision-log.md`。

## 二、补齐节奏

| 时间点 | 动作 | 处理 Agent | 说明 |
| --- | --- | --- | --- |
| T+0 | 形成确认事项 | 执行 Agent | 使用 `communication-message-pack.md` 口径，登记 `outbound-message-dispatch-log.md` |
| T+0.5 天 | 第一次补齐检查 | 执行 Agent | 确认可回写字段是否完整，并登记 `out-001-followup-evidence-register.md` |
| T+1 天 | 第二次补齐检查 | 审计 Agent | 明确缺口、目标文件和补齐时间 |
| T+2 天 | 裁决处理 | 项目负责人 / 审计 Agent | 登记 `out-001-followup-evidence-register.md` 和 `blocker-escalation-decision-log.md` |
| T+3 天 | 门禁复核 | 审计 Agent | 判断保持 No-Go、Partial Go 或形成裁决结论 |

```text
当前服务广场第一轮联调仍有 P0 确认事项未补齐，影响首次真实联调 Go / No-Go 判断。

未补齐事项：
-

影响：
-

建议处理：
1. 由对应 Agent 补齐目标台账。
2. 如无法补齐，项目负责人确认替代方案或继续保持 No-Go。
3. 如只有单板块满足条件，可按 Partial Go 判断。
```

## 五、裁决登记要求

凡是进入 T+2 裁决处理的事项，必须同步登记到 `out-001-followup-evidence-register.md` 和 `blocker-escalation-decision-log.md`，并在裁决后更新确认事项表、确认结果登记表、门禁状态和问题池。
