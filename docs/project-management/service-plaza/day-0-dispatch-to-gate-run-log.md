## 三、单条流水推进规则

每个确认事项必须按以下顺序推进，不允许跳步：

| 顺序 | 动作 | 必须更新 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 本地确认事项 | `outbound-message-dispatch-log.md` | 有确认人、确认方式、确认时间、处理截止时间 |
| 2 | 登记确认证据 | `out-001-dispatch-evidence-register.md` | 有证据编号、证据类型、证据位置、是否可追溯 |
| 3 | 更新确认事项状态 | `external-confirmation-tracker.md` | 对应 EXT 状态从待确认变为已确认或待补齐 |
| 4 | 设置补齐节奏 | `reply-followup-cadence.md`、`out-001-followup-evidence-register.md` | 下一步补齐动作明确 |
| 5 | 登记确认结果 | `reply-intake-tracker.md` | 对应 RPLY 状态从待确认变为已确认、信息不完整或待补齐 |
| 6 | 复核确认完整性 | `reply-completeness-review.md` | 明确完整、信息不完整、需裁决、不进入第一轮或无效 |
| 7 | 按批次处理确认结果 | `reply-processing-batch-log.md` | 确认结果进入处理批次 |
| 8 | 逐条回写目标台账 | `reply-ledger-update-checklist.md` | 负责人、主动作、Handoff、平台或验收台账已更新 |
| 9 | 复核门禁 | `reply-to-gate-transition.md`、`first-integration-go-checklist.md`、`phase-gate-status.md`、`phase-gate-evidence-matrix.md` | 输出 Go / Partial Go / No-Go |
| 10 | 执行一致性审计 | `consistency-and-gate-audit.md` | 状态页、报告、看板、门禁结论一致 |

## 五、门禁不允许跳过的条件

| 门禁 | 不允许跳过的前置 |
| --- | --- |
| 正式召开第一轮联调启动会 | Day 0 确认登记、确认证据、确认事项状态和会前转换判断 |
| 首次真实联调 Go | 负责人、主动作、路由、账号、数据、Handoff 质量复核、确认完整性复核、逐条台账回写 |
| 单板块 Partial Go | 对应板块责任边界、主动作、路由或临时页、账号数据、Handoff 均完整并已回写 |
| 问题关闭 Go | 有真实联调记录、问题池、关闭或延期结论 |
| 第一阶段验收 Go | 有联调记录、问题关闭结论、验收证据和验收执行记录 |
