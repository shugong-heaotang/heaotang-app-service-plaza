# 三大核心服务第一阶段最小可交付范围

本文件定义生命导航、俱乐部联盟、健康大管家在第一阶段的最小可交付范围。正式进入联调前，板块 Agent 必须补齐确认记录、接入卡和 Handoff，项目负责人按证据裁决门禁。

## 一、定义原则

第一阶段只要求主链路打通，不要求完整业务闭环。

每个核心服务至少具备：

1. 一个服务广场入口。
2. 一个目标页面或临时承接页。
3. 一个用户主动作。
4. 一个后台、管理端或临时台账处理路径。
5. 一个用户状态反馈。
6. 一份可复核的 Handoff 记录。

## 二、生命导航

第一阶段定位：承接用户进入生命导航，并完成一次基础测评、目标选择或咨询申请。

最小主链路：

```text
进入服务广场
点击生命导航
进入生命导航首页或临时承接页
提交导航申请或选择目标
后台记录申请或生成状态
用户看到提交成功或待处理状态
```

| 项目 | 要求 | 状态 |
| --- | --- | --- |
| 入口 | 服务广场展示“生命导航” | 已定版 |
| 页面 | 生命导航首页或临时承接页 | 待补齐 |
| 主动作 | 推荐：提交导航申请；备选：目标选择 / 测评提交 | 待补齐 |
| 后台处理 | 能记录用户提交结果 | 待补齐 |
| 状态反馈 | 提交成功、待处理、异常提示 | 待补齐 |
| Handoff | 需求给开发 Handoff | 待补齐 |

## 三、俱乐部联盟

第一阶段定位：承接用户查看俱乐部分类，并完成一次加入、申请或创建意向。

最小主链路：

```text
进入服务广场
点击俱乐部联盟
进入俱乐部联盟首页或临时承接页
选择俱乐部分类
提交加入、申请或创建意向
后台记录申请或进入审核
用户看到提交成功、审核中或待处理状态
```

| 项目 | 要求 | 状态 |
| --- | --- | --- |
| 入口 | 服务广场展示“俱乐部联盟” | 已定版 |
| 分类 | 公益俱乐部、自建俱乐部、家庭俱乐部、俱乐部友联体 | 已定版 |
| 管理中心 | 作为俱乐部联盟附属操作 | 已定版 |
| 页面 | 俱乐部联盟首页或临时承接页 | 待补齐 |
| 主动作 | 推荐：申请加入俱乐部；备选：创建申请 / 查看详情 | 待补齐 |
| 后台处理 | 能记录申请或审核状态 | 待补齐 |
| 状态反馈 | 提交成功、审核中、无权限、异常提示 | 待补齐 |
| Handoff | 需求给开发 Handoff | 待补齐 |

## 四、健康大管家

第一阶段定位：承接用户发起一次健康咨询、服务预约或健康档案入口访问。

最小主链路：

```text
进入服务广场
点击健康大管家
进入健康大管家首页或临时承接页
提交健康咨询、预约或查看健康档案入口
后台记录咨询或预约
用户看到提交成功、待处理或预约状态
```

| 项目 | 要求 | 状态 |
| --- | --- | --- |
| 入口 | 服务广场展示“健康大管家” | 已定版 |
| 页面 | 健康大管家首页或临时承接页 | 待补齐 |
| 主动作 | 推荐：提交健康咨询；备选：服务预约 / 健康档案入口 | 待补齐 |
| 后台处理 | 能记录咨询或预约 | 待补齐 |
| 状态反馈 | 提交成功、待处理、异常提示 | 待补齐 |
| Handoff | 需求给开发 Handoff | 待补齐 |

## 五、范围外事项

- 完整生命导航十维度内容体系。
- 完整俱乐部运营后台。
- 完整健康档案和医疗服务闭环。
- 支付、复杂订单、复杂审核流。
- AI 个性化推荐。
- 所有常用服务完整接入。
