# 俱乐部联盟 H2 会员首页需求变更与派发

日期：2026-07-12  
基线：`6149504`（服务广场权威 integration）  
结论：需求变更 Accepted；H2-M0 可独立准备，H2 页面实现等待 CA-SC 当前切片集成后激活。

## 已确认事实

- CA-H1 M1-M4 已 Full Go，H1 是目录、路由、权限、状态、响应式与遥测底座。
- 当前首页以四个分类动作和附属管理中心为中心，尚未提供“我的俱乐部、今日待办、最近活动”的会员工作台。
- 友联体在现有权威合同中已是 `club-federation` 关系，不是 ClubType；本次只修正会员呈现层级，不破坏该合同。
- CA-SC 首个会员侧闭环已经派发并有 active 合同工作项，未来前端计划与 Club Alliance 父页面发生路径重叠。

## 采用方案

采用“需求立即冻结、代码按检查点顺序实施”：

1. 不回退 H1，不把新业务混入已验收提交。
2. H2-M0 先冻结会员首页 view model、数据责任、隐私、状态和 API 缺口。
3. CA-SC 当前切片受控集成后，从新的 exact integration base 创建 H2 专用工作树。
4. H2-M1/M2/M3 依次完成页面壳、真实接入和分身份 UAT。

## 依赖与阻塞

- `blocks`：H2-M1 及后续阻塞于 CA-SC 当前合同/后端/前端的受控集成与无重叠工作树。
- `does_not_block`：H2-M0 纯需求、Schema、fixtures 和 conformance 设计；CA-SC 自身继续按既有任务书推进。
- 若 H2-M0 发现需要新的聚合 API，不得扩大 H2 前端权限；由平台/后端建立独立工作项。

## 下一授权

平台完成本派发检查单、100 分考试、实施记录和协作登记后，创建 H2-M0 模块任务；H2-M0 只允许需求与机器合同，不允许页面、后端、部署或生产。
