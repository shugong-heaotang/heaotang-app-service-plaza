# 服务广场联调到验收转换规则

本文件用于把首次真实联调结果转换成第一阶段验收门禁结论。执行 Agent 完成联调记录后，由平台 Agent、板块 Agent、验收 Agent 和审计 Agent 复核本地台账证据，最终由项目负责人判断是否可以进入验收。

## 一、转换原则

1. 联调完成不等于验收通过，必须先形成联调记录、问题关闭结论和验收前置证据。
2. 主链路阻塞问题未关闭或未明确延期前，不进入第一阶段验收。
3. Partial Go 联调只允许对已完成联调和问题关闭的板块进入验收判断，未联调板块继续保持 No-Go。
4. 验收结论必须写入 `phase-1-acceptance-checklist.md`，不能只停留在口头确认或临时记录。
5. FE-GATE 和 FE-ACC 必须按 `fact-evidence-submission-control-board.md` 的顺序进入 `fact-evidence-review-run-log.md` 复核；未复核前不得进入验收或写成验收通过。

## 二、转换输入

| 输入 | 文件 | 必须具备 |
| --- | --- | --- |
| 联调门禁结论 | `first-integration-go-checklist.md` | Go 或 Partial Go |
| 联调实际记录 | `round-1-integration-run-record.md` | 通过项、失败项、新增问题、下一步动作 |
| 问题关闭结论 | `round-1-issue-closure-tracker.md` | 主链路问题关闭或延期 |
| Handoff 记录 | `round-1-handoff-forms.md`、`handoff-log.md`、`handoff-quality-review.md` | 联调给测试 handoff 已记录并通过质量复核 |
| 测试账号和数据 | `test-accounts-and-data.md` | 账号、数据和证据状态已更新 |
| 路由和页面证据 | `routing-and-temporary-page-spec.md` | 路由可访问或临时承接页可访问 |
| 事实证据复核 | `fact-evidence-submission-control-board.md`、`fact-evidence-review-run-log.md` | FE-GATE、FE-ACC 已按顺序提交、复核和回写 |
| 验收证据登记 | `acceptance-evidence-register.md` | 每个验收项有证据编号或补证动作 |

## 三、第一阶段验收触发条件

验收触发只表示“可以开始执行第一阶段验收”，不表示验收通过。触发条件必须同时满足证据、问题、Handoff 和裁决四类要求；任一要求缺失时，第一阶段验收保持 No-Go。

| 触发项 | 最低要求 | 证据编号 | 触发失败时结论 |
| --- | --- | --- | --- |
| 联调门禁达到可转换状态 | `first-integration-go-checklist.md` 为 Go，或明确 Partial Go 的板块范围 | EV-001、EV-003 | 不进入验收 |
| 首次真实联调已记录 | 联调范围、环境、执行 Agent、通过项、失败项、问题编号和下一步动作齐全 | EV-003 | 不进入验收 |
| 主链路阻塞问题有关闭结论 | 阻塞问题已关闭；如延期，必须证明不阻塞第一阶段验收范围 | EV-004 | 不进入验收 |
| 联调给测试 Handoff 完成 | Handoff 表单、日志和质量复核均可追溯 | EV-005 | 不进入验收 |
| 路由、权限、账号、数据前置证据齐全 | 服务广场入口、核心入口、权限、空状态、异常状态均有证据编号或补证动作 | EV-006、EV-008、EV-009 | 不进入验收 |
| FE-GATE 门禁复核完成 | `fact-evidence-review-run-log.md` 已登记联调后门禁复核事实，且未发现阻断验收的问题 | FE-GATE-001 | 不进入验收 |
| FE-ACC 验收事实提交完成 | `fact-evidence-intake-review.md` 已接收 FE-ACC 相关事实，`fact-evidence-review-run-log.md` 已形成复核记录 | FE-ACC-011 至 FE-ACC-013 | 不形成最终验收结论 |
| 验收执行记录已准备 | `phase-1-acceptance-run-record.md` 已具备可填写字段，等待真实执行 | EV-011 | 可准备，但不得写通过事实 |
| 项目负责人裁决口径明确 | 裁决人、裁决依据、Go/No-Go 口径和保留风险字段已准备 | EV-012 | 不形成最终验收结论 |

## 四、联调记录完整性

`round-1-integration-run-record.md` 必须满足：

| 检查项 | 完整标准 |
| --- | --- |
| 基本信息 | 联调日期、环境、执行 Agent、范围已填写 |
| 联调前检查 | Agent 分工、主动作、Handoff、路由、账号、数据均有状态和本地台账证据 |
| 路径记录 | 服务广场入口、核心服务入口、主动作、权限、空状态、异常状态均有实际结果 |
| 问题编号 | 失败项必须有问题编号或明确“不阻塞验收”的说明 |
| 联调结论 | 明确是否进入验收、下一步动作和下一次联调时间 |

缺任一项，问题关闭阶段保持 No-Go。

## 五、问题关闭判定

| 问题类型 | 处理要求 | 是否允许验收 |
| --- | --- | --- |
| 阻塞主链路 | 必须关闭，并提供关闭证据 | 未关闭不允许 |
| 不阻塞主链路 | 可延期，但必须写明补齐 Agent、延期原因、后续阶段 | 可允许 |
| 架构边界问题 | 必须由项目负责人裁决 | 未裁决不允许 |
| 路由、权限、账号、数据问题 | 必须由平台 Agent 给出关闭或延期结论 | 无结论不允许 |
| 板块业务规则问题 | 必须由板块 Agent 补齐确认结果 | 无确认不允许 |

## 六、验收进入条件

### 1. 整体进入验收

三大核心服务全部完成以下条件，整体进入第一阶段验收：

| 条件 | 状态要求 |
| --- | --- |
| 三大核心服务均完成首次真实联调 | 已完成 |
| 主链路阻塞问题全部关闭 | 已关闭 |
| 非阻塞问题延期处理明确 | 已登记 |
| 联调给测试 Handoff 完成 | 已提交 |
| 验收前置证据齐全 | 已补充 |

### 2. 单板块进入验收

Partial Go 情况下，单个核心服务满足以下条件，可以进入该板块验收：

| 条件 | 状态要求 |
| --- | --- |
| 该板块完成首次真实联调 | 已完成 |
| 该板块主动作通过或有可接受替代方案 | 已确认 |
| 该板块主链路阻塞问题关闭 | 已关闭 |
| 该板块联调给测试 Handoff 完成 | 已提交 |
| 未进入验收的板块阻塞原因明确 | 已登记 |

## 七、Go / No-Go 判定口径

| 判定 | 使用条件 | 必须记录 | 禁止事项 |
| --- | --- | --- | --- |
| Go | 所有触发条件满足，验收执行记录有真实通过结果，项目负责人明确允许进入下一阶段 | 通过项、证据编号、裁决时间、裁决人、保留风险 | 不得用“计划完成”“待补充”替代真实证据 |
| Partial Go | 仅部分板块满足触发条件，且未进入验收板块的阻塞原因和隔离边界明确 | 进入验收板块、未进入板块、隔离边界、证据编号、裁决人 | 不得把未联调或未关闭问题的板块写成通过 |
| No-Go | 任一触发条件缺失，或阻塞问题未关闭，或缺少真实验收执行记录 | 缺失条件、回退阶段、补齐 Agent、下一步动作 | 不得为了推进阶段而改写为 Go |

当前文档只能登记转换规则和触发口径。没有真实联调记录、问题关闭结论、Handoff 质量复核和项目负责人裁决时，不得在本文件中写入“已进入验收”或“验收通过”。

## 八、转换动作

| 步骤 | 动作 | 负责人 | 输出 |
| --- | --- | --- | --- |
| 1 | 填写首次联调记录 | 执行 Agent | `round-1-integration-run-record.md` |
| 2 | 把失败项登记为问题 | 执行 Agent | `round-1-issue-closure-tracker.md` |
| 3 | 关闭或延期主链路问题 | 平台 Agent、板块 Agent | 问题关闭结论 |
| 4 | 补齐联调给测试 Handoff | 板块 Agent、验收 Agent | `round-1-handoff-forms.md`、`handoff-log.md` |
| 5 | 复核验收前置证据 | 审计 Agent | `phase-1-acceptance-checklist.md` |
| 6 | 登记或补齐验收证据 | 验收 Agent、平台 Agent | `acceptance-evidence-register.md` |
| 7 | 登记 FE-GATE 和 FE-ACC 复核流水 | 审计 Agent | `fact-evidence-review-run-log.md` |
| 8 | 更新阶段门禁 | 审计 Agent、项目负责人 | `phase-gate-status.md` |
