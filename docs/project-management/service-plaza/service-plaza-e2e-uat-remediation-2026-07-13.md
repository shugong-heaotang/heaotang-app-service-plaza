## 根因链与修复

### RC-1 深链接回到老页面

- 症状：从会员首页进入俱乐部、待办或活动时可能离开 `/app/service-plaza`，直接访问项目总览或未知子路径也会加载父级旧应用。
- 复现：内部链接使用原生 `<a href>`；Nginx 仅有通用 `/app/` fallback 到 `/app/index.html`。
- 根因链：原生导航绕过 BrowserRouter basename + 子应用没有独立服务器 fallback -> 请求落入父应用 -> 用户看到老页面。
- 系统修复：会员首页内部目标改用 React Router `Link`；测试服务器为 `/app/service-plaza/` 增加独立 fallback；部署脚本强制校验六条代表性深链接加载同一版本资产。
- 回归：项目总览、活动路径和未知路径均返回 200，并引用服务广场新资产。

### RC-2 退出后敏感草稿仍留在页面

- 症状：生命导航退出后，当前备注和反馈仍存在；同一标签页换账号时可能看到上一账号草稿。
- 根因链：会话状态改变只重新拉取历史，没有清理组件本地状态 -> 账号边界与页面状态边界不一致。
- 系统修复：未认证时清空备注、反馈、提交状态和历史加载态；新会话成功后清除陈旧登录提示；新增 A 账号退出、B 账号登录回归。

### RC-3 权限拒绝没有用户可见反馈

- 症状：无 `club:manage` 权限点击管理中心后页面不跳转，也没有解释。
- 根因链：运行时只派发内部事件，没有渲染全局可见消息 -> 审计有记录但用户误认为按钮失效。
- 系统修复：保留审计事件，同时显示全局权限/登录要求提示；新增无权限可见反馈回归。

### RC-4 健康页暴露联调开关且空诉求可提交

- 症状：测试服务器公开显示“第一阶段联调”和正常/无权限/空/错误切换；仅填写姓名即可请求后端。
- 根因链：开发辅助控件未按构建模式隔离 + 前端仓储缺少症状必填校验。
- 系统修复：辅助控件仅在 development 模式显示；空健康诉求在客户端失败关闭且不发网络请求。

### RC-5 登录和全局会话可用性不完整

- 症状：验证码只校验非空；服务广场与俱乐部页没有统一的当前用户和退出入口。
- 系统修复：验证码必须为六位数字；AppFrame 提供统一会话条和退出入口，避免各模块重复实现。

### RC-6 俱乐部入口显示内部状态词

- 症状：四类入口直接显示英文 `active`，容易被理解为全部业务已完成。
- 系统修复：改为“入口可访问”等用户语言；聚焦页继续明确说明具体业务需子项目门禁后开放。
