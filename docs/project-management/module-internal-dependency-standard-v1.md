# 和奥堂板块内部依赖标准 v1

## 两层依赖

1. 平台级依赖由 `foundation-capabilities.v1` 和每个板块的 `module-dependencies.v1` 声明，解决所有板块共用的身份、API、权限、配置、工具链、追溯和发布恢复。
2. 板块内部依赖由 `module-internal-dependencies.v1` 声明，解决该板块内部的接口、数据、业务政策、配置、工作流和验收顺序。

每个业务切片都先完成两层依赖，再进入功能实现。平台依赖不因单一业务变化；内部依赖只在所属板块内演进，不能反向污染公共层。

## 状态和门禁

- `draft`：边界或规则仍未确定，阻塞依赖它的业务开发。
- `standardized`：接口/数据/规则已经形成契约，可以开始实现。
- `implemented`：代码存在但尚未形成完整环境证据。
- `verified`：自动化和测试环境证据均通过。
- `development_readiness=go`：首切片所有必需内部依赖至少已标准化。
- `acceptance_readiness=go`：首切片所有必需内部依赖均已验证。

板块内部依赖同样禁止绕行：例如健康 AI 同意未标准化，就关闭 AI 能力，不允许直接发送健康正文；俱乐部审核事务失败，就保持申请 pending，不允许先改状态；价格未配置，就显示待配置并拒绝收费。
