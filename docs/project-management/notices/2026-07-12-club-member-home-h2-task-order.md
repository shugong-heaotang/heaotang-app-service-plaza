# 俱乐部联盟 H2 会员首页正式任务书

- 通知编号：`CA-H2-TASK-20260712-001`
- 需求来源：项目负责人 2026-07-12 会员视角首页评审
- 上游：CA-H1 M1-M4 Full Go；CA-SC 首个会员侧闭环完成后方可激活页面实现
- 平台派发工作项：`AIW-20260712-CLUB-MEMBER-HOME-DISPATCH`
- 模块工作项：`AIW-20260712-CLUB-MEMBER-HOME-H2`
- 负责人：俱乐部联盟负责人

## 1. 决策

需求现在冻结，当前已 Go 的 H1 技术底座不推翻、不降级。H2 在 CA-SC 当前活动切片受控集成后，以独立工作树实施“会员工作台在上、联盟分类探索在下”的双层首页。

H1 只证明独立路由、四入口目录、权限、生命周期、八态、响应式、遥测和零越界网络请求；不得再把 H1 描述为最终会员首页。

## 2. 组织语义

1. 俱乐部联盟是最高统筹机构。
2. 联盟管理三类俱乐部：直营公益俱乐部、家庭俱乐部、自建俱乐部。
3. 公益仍使用权威组合 `type=standard + category=charity`，不得新增 charity ClubType，也不得伪装为 direct。
4. 自建仍使用权威组合 `type=standard + category=general`。
5. 家庭仍使用 `type=family`，完整产品语义由 CA-FC 子项目冻结。
6. 俱乐部友联体是 `relationship_kind=club-federation` 的俱乐部间合作关系，不是第四种 ClubType；首页可保留“友联体”探索入口，但不得让会员误解为第四类下属俱乐部。

## 3. 会员首页信息架构

登录会员首页从上到下固定为：

1. 会员摘要：称呼、已加入俱乐部数、待办数、未读数；不得暴露敏感身份或联系方式。
2. 我的俱乐部：优先展示已加入或已创建的俱乐部、本人角色、最近状态和唯一进入动作。
3. 今日待办：只聚合当前用户有权处理且可追溯来源的事项。
4. 最近活动：已报名、即将开始或与本人俱乐部相关的活动。
5. 联盟动态/推荐：必须有明确来源和排序规则；无可信数据时隐藏或显示空态，不伪造推荐。
6. 探索更多：公益、自建、家庭、友联体四个既有上游动作入口继续从 `service-plaza.action.v1` 派生。

未登录用户不显示伪造的“我的”数据，继续进入共享登录承接或只读联盟入口。管理中心保持附属入口，仅在真实 `club:manage` 权限允许时激活，普通会员不展示管理复杂度。

## 4. 状态与优先级

会员首页必须区分：无俱乐部、已加入、申请中、被拒绝、已退出、俱乐部暂停/解散、局部数据失败、整体错误。局部板块失败不得用空数组伪装成功；同时不得因非关键推荐失败阻断“我的俱乐部”。

排序原则：会员事实优先于探索分类；待办按紧迫性与时间排序；同级排序必须来自版本化合同或服务端权威字段，不在组件中硬编码业务数值。

## 5. 连续检查点

### H2-M0：需求与数据合同

- 冻结页面 view model、字段来源、隐私等级、空态/错误态、权限和排序。
- 明确哪些现有 API 可复用、哪些缺口必须独立提交平台/后端变更请求。
- 建立机器 Schema、fixtures、稳定错误 ID 和合成 conformance。
- 本检查点禁止前端业务页面、后端、部署和真实数据。

### H2-M1：会员首页页面壳

- 使用 H2-M0 合同和受控 fixtures 实现双层页面壳。
- 复用 H1 的路由、ActionControl、权限、生命周期、遥测和八态，不复制公共实现。
- 覆盖 320/360/768/桌面、键盘、焦点、aria、局部错误与空态。
- 模拟数据只用于组件测试，不得作为运行时回退。

### H2-M2：真实数据接入

- 接入经 H2-M0 接受的“我的俱乐部、本人申请、待办、活动、未读”能力。
- 每项 API 单独授权；服务端强制本人资源归属和权限，前端不得代替授权。
- 缺失公共能力时单独派发，禁止在页面中复制 API/auth/retry/error 实现。

### H2-M3：测试环境分身份 UAT

- 新会员、家庭俱乐部普通会员、多俱乐部会员、主任/管理员至少四种身份。
- 验证直达/刷新/后退/返回、无数据、局部失败、无权限、暂停/解散、移动端和桌面。
- 保存 route、exact commit、环境、DOM、网络 allow/deny、遥测和服务端关联证据；不得记录 OTP/JWT。

## 6. 激活门禁与范围冲突

当前 `AIW-20260712-CLUB-SC-P0-P1-CONTRACTS` 为 active，且后续 CA-SC 前端计划修改 Club Alliance 父页面。H2 页面实现保持 planned，只有在 CA-SC 合同、后端和前端受控集成，权威 integration 基线明确且工作树 clean 后才能激活。H2-M0 的纯需求/合同路径若与 CA-SC 无重叠，可先独立派发。

## 7. 禁止范围

- 不修改服务广场已锁定核心 IA。
- 不把友联体改成 ClubType，不复用 FamilyAlliance。
- 不在首页实现创建、审核、成员管理、支付、退款、提现、订阅或生产操作。
- 不以 mock、静态数组或 catch 后空数组冒充真实会员数据。
- 不在未通过独立部署授权前访问生产或不可逆数据。

## 8. 验收结论口径

- H2-M0 Go：只证明需求与数据合同可实现。
- H2-M1 Go：只证明页面壳与合成状态通过。
- H2-M2 Go：只证明真实接口集成通过本地/集成门禁。
- H2-M3 Full Go：必须有测试环境真实分身份浏览器证据。
