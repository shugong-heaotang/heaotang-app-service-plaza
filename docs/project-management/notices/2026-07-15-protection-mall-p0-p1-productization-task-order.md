# 保障商城 P0/P1 产品化任务书

## 执行顺序

1. 模块运行时工作项先实现只读目录页、共享 API adapter 接入、严格运行时解码、加载/空/错/重试、请求取消和重复请求抑制、键盘与焦点可达性、模块测试与 Handoff。
2. 模块候选独立验收 Go 后，平台共享接线工作项才可激活，负责 `App.tsx` 路由、路由测试和 APP 质量 CI。
3. 两项均受控集成后才可进入测试服 UAT；本任务不授权部署或上线。

## P0

- 只使用 `businessApiAdapter`；不得复制认证、信封解析、request ID、超时、重试或幂等逻辑。
- 目录 API 使用版本化 `/api/v1/mall/catalog` 读取边界；后端路由尚未授权时必须显示可恢复错误，不得用假成功掩盖。
- 严格校验 `mall.catalog.v1`、商品类型、责任主体、价格快照与权益快照；错误数据失败关闭。
- 同一时刻只保留一个有效读取；重试或切换场景必须取消旧请求并忽略迟到响应。
- 明确 loading、empty、error、success 四态，错误展示 request ID（如有）和可键盘触发的重试。

## P1

- 场景筛选、商品语义化列表、价格 minor-unit 安全格式化、保障权益授予延后提示。
- 焦点可见、标题层级、状态播报、44px 触控目标和窄屏布局。
- Vitest + Testing Library 覆盖正常、空、错误、重试、取消、迟到响应、畸形载荷、键盘操作与重复请求抑制。
- 平台接线阶段增加独立路由与质量 CI；CI 至少运行 `npm test`、`npm run build` 和 UTF-8 门禁。

## No-Go

数据库、真实路由实现、下单、支付、退款、对账、回调、真实资金、真实会员/商家数据、短信、部署、生产和上线全部禁止。任何写能力必须另立工作项。
