## 二、任务目标与接口基线

登录用户从 `/services/club-alliance?category=自建俱乐部` 浏览后端权威筛选的 `type=standard` 俱乐部，幂等提交加入申请，查看本人申请状态；俱乐部管理者只审核本俱乐部 pending 申请，批准时成员写入与申请状态在同一事务中成功。

| 项目 | 当前基线 |
|---|---|
| 服务 ID | `club-alliance` |
| 返回路径 | `/services` |
| 列表/详情 | `GET /api/v1/clubs`、`GET /api/v1/clubs/:id` |
| 加入申请 | `POST /api/v1/clubs/:id/join`，必须携带 `Idempotency-Key` |
| 管理者待审 | `GET /api/v1/clubs/:id/join-applications` |
| 审核 | `PUT /api/v1/clubs/:id/join-applications/:aid/review` |
| 本人状态 | M1 必须先确认并冻结；现阶段不得伪造前端状态 |
| 自建筛选 | M1 必须验证 `type=standard` 的后端权威过滤；不得前端标签伪筛选 |

已知本人状态接口和 `type=standard` 权威筛选尚未完成验收，因此 M1 的目标是取得运行事实并形成最小兼容接口申请，不得通过前端假数据绕过。

本切片不做家庭/公益俱乐部、友联体、会费、支付、提现、分账、付费套餐和完整管理中心。任何价格、比例、名额或有效期必须来自经双人审核的后台配置，未配置时失败关闭。
