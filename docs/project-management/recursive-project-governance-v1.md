# 和奥堂递归项目治理标准 v1

任何板块、模块或重要切片，只要被称为“项目”，都执行同一套最小治理包。

## 最小治理包

1. 唯一项目 ID、负责人和父项目集成负责人。
2. 项目 README：目标、范围、非目标、当前状态、必读顺序和下一检查点。
3. 正式任务通知书：接口、技术栈、依赖、允许修改范围、验收标准和时间盒。
4. 平台依赖与内部依赖图均达到 development Go。
5. 独立 `codex/` 分支和工作树，活动范围不与其他项目重叠。
6. 文件级起飞检查单和 100 分随机治理考试。
7. 每个可测试切片的实施记录、自动化测试、证据和 Handoff。
8. 测试环境验收、回滚路径和最终集成结论。

## 父子项目职责

| 角色 | 负责 | 不负责 |
|---|---|---|
| 平台集成负责人 | 下达任务、锁定公共接口、提供平台依赖、阶段抽查、最终验收与合并 | 代替板块负责人完成全部业务代码 |
| 板块负责人 | 阅读课程并通过考试、完成板块内部设计与实现、提交阶段证据、关闭根因问题 | 私自修改平台受保护契约或绕过门禁 |

## 分段验收

一个检查点最多包含一个最小可测试成果，通常控制在 2–4 个有效工程小时内。每次提交：变更路径、契约差异、测试结果、未决风险、根因状态和下一步。平台负责人可以抽查源代码、复跑测试或进行测试环境验证；未通过的检查点不得进入下一个检查点。

最终验收不能替代过程检查。过程检查也不能替代最终跨模块验收。
