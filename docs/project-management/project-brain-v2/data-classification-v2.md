# Project Brain v2 数据分级与首期准入

| 等级 | 类别 | M0/M1 首期策略 | 示例 |
| --- | --- | --- | --- |
| G0 | 公开或内部治理元数据 | 可按角色和用途读取 | 工作项 ID、阶段、Owner、门禁结论 |
| G1 | 去标识经营聚合 | M1 合同和独立审查后条件允许 | 满足阈值的趋势、计数、转化率 |
| P1 | 行级会员、商家或活动参与数据 | 禁止 | 会员、联系方式、报名人、商家联系人 |
| H1 | 行级健康数据及健康推断 | 严禁 | 咨询、病史、风险标签、医生意见 |
| F1 | 行级交易资金数据 | 严禁 | 订单、支付、退款、余额、流水 |
| C1 | 行级客服内容 | 严禁 | 工单、投诉、聊天、录音、附件 |
| S1 | 凭据与安全秘密 | 严禁 | Token、密码、私钥、环境变量 |

## 1. G0 项目治理事实

G0 仅包含完成项目管理所需的事实，例如工作项、角色、状态、依赖、检查单、考试、IR、Handoff、验收结论和 Git 证据。

G0 不因属于治理数据而自动公开。访问仍须满足角色、用途和最小化要求；备注中不得夹带真实会员、健康、交易或客服内容。

## 2. G1 去标识经营聚合

“聚合”不等于自动安全。G1 必须同时满足：

- 数据最小化；
- 经批准的最小群体阈值；
- 时间、地域和维度组合的重识别评估；
- 小样本抑制；
- 敏感维度抑制；
- 禁止下钻到个人或单笔记录；
- 禁止与未授权数据拼接；
- 口径和阈值版本化；
- permitted use 明确；
- Owner、freshness、质量和证据齐全。

阈值未配置、样本不足或存在合理重识别风险时，必须输出 `Unknown/No-Go`，不得展示猜测值、零值或精确小计。

## 3. 明确禁止的行级数据

首期以及 M0 均严禁：

- 会员身份、联系方式、画像、关系和行为；
- 健康咨询、病史、检查、诊断、建议、风险标签；
- 订单、支付、退款、余额、资金流水和交易主体；
- 客服工单、投诉、聊天、录音和附件。

若未来业务提出上述需求，必须停止当前阶段，进行隐私、安全、法律和架构重新立项，不得通过扩展 G1 口径绕过。

## 4. 来源责任

- source owner 对业务定义、准确性和 freshness 负责。
- v2 项目负责人维护只读映射和准入证据，不接管源系统所有权。
- 安全/隐私负责人决定数据分类和准入。
- 独立 reviewer 验证阈值、最小化和负向证据。
- 平台集成负责人控制受保护接口和集成，不改变业务口径。
- Owner 或 authority 不明确时，指标状态为 `Unknown`。

## 5. 审计字段

每次未来读取至少记录：

- 运行 ID；
- 事实 ID；
- authority 与来源版本/hash；
- source owner；
- 口径版本；
- 数据分类；
- permitted use；
- 授权主体；
- 统计时间窗；
- freshness 结果；
- 质量结果；
- 输出 hash；
- 状态和原因码。

审计日志不得包含被禁止的行级内容、凭据或秘密。

## 6. 保留与删除原则

快照和审计的保留期必须在 M1/M4 由获批配置定义。未配置时不得自行设置永久保留，也不得启用生产。删除只作用于 Brain 的派生只读制品，不得删除或修改源系统权威事实。
