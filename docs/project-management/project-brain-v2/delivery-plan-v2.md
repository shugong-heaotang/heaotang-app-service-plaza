# Project Brain v2 分阶段交付计划

## 1. 里程碑

| 里程碑 | 交付 | 解锁条件 | 仍然 No-Go |
| --- | --- | --- | --- |
| M0 治理冻结 | 章程、需求、架构、分级、计划、验收、ADR、Handoff | checklist/exam/IR、独立 Go、受控集成 | 数据接入、代码、环境、生产 |
| M1 事实合同 | 去标识聚合与治理事实合同、来源映射、样例与负例 | M0 integrated；Owner/分级/口径/阈值/质量独立验收 | scheduler、dashboard、生产数据 |
| M2 定时刷新 | 只读 job、不可变快照、告警、审计、失败演练 | M1 integrated；幂等/互斥/失败关闭/回滚证据 | 老板生产驾驶舱 |
| M3 老板驾驶舱 | 只读 UI、状态解释、截至时间、权限负例 | M2 integrated；安全和可用性独立验收 | production enablement |
| M4 发布治理 | RBAC、审计、开关、备份/回滚与发布演练 | M3 integrated；安全审查和回滚演练 Go | 未单独批准的生产启用 |
| M5 最终验收 | 跨阶段证据、Handoff、受控集成 | M4 Go；独立验收；fresh authority | 任何隐式生产发布 |

## 2. M1 解锁要求

M1 工作项必须单独登记，并至少交付：

- 治理事实合同；
- G1 去标识聚合合同；
- authority/source owner 映射；
- 口径、阈值、freshness 和质量规则；
- permitted use 与角色；
- 合法样例；
- 行级数据、小样本、过期、冲突和权限失败负例；
- 独立数据分级和重识别审查。

M1 不得顺带实现 scheduler 或 dashboard。

## 3. M2 解锁要求

M2 必须证明：

- scheduler 只有只读能力；
- 运行幂等且有并发互斥；
- 重试有上限；
- 失败可告警和升级；
- 失败不覆盖最后可信快照；
- 输入、输出和运行证据可审计；
- 禁用和回滚可演练；
- 无真实生产启用。

## 4. M3 解锁要求

M3 必须证明：

- dashboard 只有只读查询；
- 服务端权限真实生效；
- 未授权角色、直接 URL、接口调用和导出全部拒绝；
- 页面展示截至时间、来源、口径和状态；
- `Unknown/No-Go` 可解释；
- 不存在行级敏感数据下钻；
- 生产仍默认关闭。

## 5. M4 解锁要求

M4 必须完成：

- 角色和最小权限矩阵；
- 审计完整性；
- 独立 production 开关；
- 发布前检查；
- 禁用、回滚、恢复演练；
- 生产构建零默认快照；
- 安全、隐私和发布负责人独立 Go。

M4 Go 仍不自动执行生产启用；启用需单独授权和明确时间窗。

## 6. M5 收口要求

M5 汇总 M0-M4 的精确证据，完成独立验收、Handoff、freshness 审计和平台受控集成。不得用代码存在、候选提交、自测通过或分支推送替代独立验收。

## 7. 主要风险与控制

- 多权威和口径漂移：唯一 authority、版本化口径、冲突 `No-Go`。
- 敏感数据越界：分级、阈值、小样本抑制、禁止下钻、负向测试。
- 陈旧数据误导：freshness SLO、显式 stale/Unknown、失败不覆盖。
- AI 或运营误写源系统：只读凭据、接口 allowlist、无写端口、审计验证。
- “已合并即上线”：环境开关默认关闭、M4 单独审批、发布与回滚演练。
- Owner 不履责：指标保持 Unknown，升级项目最高负责人，不由 Brain 代填。
- 去标识失效：立即停用指标、保留证据、重新分级和重审 ADR。

## 8. 组织推进规则

每个里程碑都由项目负责人交付、独立 reviewer 验收、项目最高负责人批准、平台集成负责人集成。失败只阻塞下游，不扩大授权；其他不重叠项目可以继续。
