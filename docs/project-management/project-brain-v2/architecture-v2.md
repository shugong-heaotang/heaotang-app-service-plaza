# Project Brain v2 经营只读架构

## 1. 逻辑链

`权威来源 -> 只读适配器 -> 口径/权限/质量校验 -> 不可变快照 -> 只读查询模型 -> 老板驾驶舱`

scheduler 只触发读取、校验和生成新快照，不得调用源系统写接口。dashboard 只查询已授权的只读模型，不直接访问业务数据库，不提供编辑、审批、重算或回写按钮。

M0 只冻结此架构，不实现上述组件。

## 2. 权威与 v1 继承

Project Brain v1 的权威文件、只读行为、显式 `Unknown/No-Go` 和失败关闭继续有效。

v2 必须：

- 通过引用和只读适配消费既有事实；
- 不复制 v1 为新的独立权威；
- 不修改 v1 合同、脚本或页面；
- 不夺取各业务 Owner 对经营指标定义和质量的责任；
- 不把快照或驾驶舱展示反向定义为源业务事实。

## 3. 来源映射模型

每个事实映射至少由以下字段组成：

`fact_id + business_definition + authority + owner + read_endpoint_or_artifact + freshness + quality + classification + permitted_use + evidence + failure_state`

每类事实只能有一个声明的 authority。若多个来源冲突，状态必须是 `No-Go`，由事实 Owner 和平台负责人裁决；Brain 不得自动挑选一个值。

## 4. 读取状态模型

一次读取结果只能进入以下状态之一：

- `Trusted`：来源唯一、在 freshness 内、质量和权限全部通过。
- `Unknown`：证据缺失、过期、不可达或无法证明。
- `No-Go`：权限、分级、质量、口径冲突或发布门禁明确失败。

不得把 `Unknown` 自动降级为上次值。若业务需要展示最后可信快照，必须同时展示：

- `stale` 标识；
- 快照时间；
- 口径版本；
- 当前失败原因；
- 责任 Owner；
- “不可用于当前决策”的提示。

## 5. 定时刷新架构约束

M2 才可实现 scheduler。每个任务必须具备：

- 幂等运行 ID；
- 单实例互斥或等价并发控制；
- 明确超时；
- 有上限的重试；
- 失败告警与升级 Owner；
- 输入 hash、输出 hash；
- 开始时间、结束时间和统一时区；
- 结果状态和原因码；
- 失败不覆盖最后可信快照；
- 无源系统写权限、无写接口、无写凭据。

scheduler 只能创建新的不可变快照或失败记录，不能修改源事实，也不能把失败结果写成成功。

## 6. 老板驾驶舱约束

M3 才可实现老板驾驶舱。驾驶舱必须：

- 使用服务端授权和最小权限；
- 不以隐藏菜单或前端路由作为安全边界；
- 展示数据截至时间、口径版本、状态、来源和 Owner；
- 解释 `Unknown/No-Go` 的原因；
- 禁止行级敏感数据下钻；
- 默认禁止导出，导出需独立授权、审计和水印策略；
- 不提供写回、审批、重算、改状态或源系统操作能力。

## 7. 权限与审计

未来读取凭据只能访问明确 allowlist 的只读接口或制品。审计至少记录：

- 主体与角色；
- 请求/运行 ID；
- 事实 ID；
- 来源和版本/hash；
- 口径版本；
- 数据分类；
- freshness 与质量结论；
- 输出快照 hash；
- 访问或刷新时间；
- 状态和原因码。

审计日志本身不得包含被禁止的行级内容或秘密。

## 8. 生产默认关闭

以下能力分别使用独立开关，并全部默认关闭：

- production route；
- production snapshot source；
- scheduled production job；
- boss dashboard；
- export；
- notification。

普通生产构建不得自动携带、生成或刷新真实快照。

## 9. 代码集成与生产启用分离

代码进入权威 Git 只表示版本完成受控集成，不代表：

- 安全验收完成；
- 生产数据获准；
- 生产路由开放；
- 定时任务启用；
- 老板驾驶舱可访问。

生产启用必须等待 M4 权限、审计、发布和回滚演练独立 Go，并获得单独授权。

## 10. 回滚原则

回滚顺序为：

1. 关闭 dashboard 和 export；
2. 停止 production job；
3. 撤销 production route；
4. 恢复上一可信只读版本或快照指针；
5. 保留失败运行、审计和证据；
6. 验证源系统事实没有被修改。

回滚不得通过修改源业务事实来“修正”驾驶舱。
