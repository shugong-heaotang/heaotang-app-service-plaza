# Project Brain v2 项目章程

## 使命

Project Brain v2 把分散的项目治理事实和合规经营聚合组织为老板可读、可追溯、失败关闭的经营只读视图。它不是新的业务主库，也不是能够修改源系统的“超级后台”。

## 成功定义

任何进入项目的负责人或 Agent 都能回答：事实来自哪里、谁负责、何时刷新、质量是否合格、是否可用于决策、为什么显示 `Unknown/No-Go`，以及谁批准进入下一阶段。老板驾驶舱只展示可证明的事实和风险，不把推测包装成事实。

## 角色关系与决策权

| 角色 | 责任 | 不得替代的角色 |
| --- | --- | --- |
| 项目最高负责人 | 决定业务目标、风险偏好和最终批准 | 不以口头批准替代证据门禁 |
| Project Brain v2 项目负责人 | 负责需求、架构、计划和交付证据 | 不自验收、不修改 registry |
| 数据/业务事实 Owner | 负责事实定义、唯一权威、质量和 freshness | 不向 Brain 让渡源系统写权 |
| 独立验收负责人 | 按冻结标准给出 Go/No-Go | 不参与实现、不降低验收标准 |
| 平台集成负责人 | 控制 registry、权威 freshness 和受控集成 | 不代替业务验收或生产批准 |
| 安全与发布审批者 | 审核最小权限、审计、发布与回滚 | 与开发、验收保持职责分离 |

开发、独立验收、最终批准和受控集成不得由同一角色包办。

## M0 范围

- 项目章程、角色和决策权。
- v1 权威及失败关闭边界继承。
- 首期数据分级和来源映射规则。
- 只读 scheduler/dashboard 架构约束。
- `Unknown/No-Go`、生产默认关闭和发布分离。
- M1-M5 解锁条件、风险、里程碑、验收和 Handoff。

## M0 非范围

M0 不写运行代码、不定义 `contracts/project-brain/v2`、不接真实数据、不创建运行时快照、不启动定时任务、不挂载 APP 路由、不部署、不启用生产。首期严禁行级会员、健康、交易资金和客服数据。

## v1 继承与架构不变量

1. Project Brain v1 在其既有范围内继续是权威；v2 只能引用，不复制、不改写、不建立第二权威。
2. 每个未来指标只有一个声明的权威来源和 Owner；Brain 永远不成为源系统写入者。
3. 来源缺失、过期、冲突、质量失败或授权不足时必须显式显示 `Unknown/No-Go`，不得由 AI 猜测或静默沿用旧值。
4. scheduler 与 dashboard 均只读、无回写能力；生产 route、snapshot、job、dashboard 默认关闭。
5. 代码集成、测试环境验证、生产启用是彼此独立的授权动作。

## 阶段门禁

| 阶段 | 交付 | 解锁前提 |
| --- | --- | --- |
| M0 | 章程、需求、架构、分级、计划、验收、ADR、Handoff | current checklist、exam100、verified IR、独立 Go、受控集成 |
| M1 | 治理事实与去标识经营聚合合同、来源映射 | M0 integrated，Owner/口径/阈值/质量独立验收 |
| M2 | 可审计只读定时刷新与不可变快照 | M1 integrated，幂等/互斥/失败关闭/告警/回滚证据 |
| M3 | 生产级老板只读驾驶舱候选 | M2 integrated，权限和可用性独立验收 |
| M4 | 权限、审计、发布和回滚演练 | M3 integrated，安全审查 Go |
| M5 | 独立总验收、Handoff 与受控集成 | M4 Go、fresh authority、明确生产授权另行决定 |

任一阶段失败只阻塞下游，不扩大授权；M0 完成也不自动授权 M1-M5 或 production。
