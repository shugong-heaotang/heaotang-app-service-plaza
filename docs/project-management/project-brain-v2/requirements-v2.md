# Project Brain v2 M0 需求与边界

## 1. 用户与决策场景

老板需要从一个只读入口了解项目进度、责任、风险、阻塞、经营趋势和证据新鲜度；项目负责人需要知道下一检查点与责任人；验收和审计角色需要追溯结论来源。任何展示都不得越权暴露个人或敏感行级事实。

## 2. 首期允许范围

### 2.1 项目治理事实

允许读取权威 registry、任务令、检查单、考试、IR、Handoff、验收结论和 Git 精确证据，形成状态、责任、风险、依赖和 freshness 视图。

### 2.2 去标识经营聚合

仅在 M1 合同另行批准后，允许使用已有权威系统产生的、达到最小群体阈值且无法合理重识别个人的聚合指标。

每项聚合必须记录：

- 业务定义与用途；
- 唯一 authority 与 source owner；
- 聚合口径和时间窗；
- 数据等级和最小群体阈值；
- freshness SLO；
- 质量规则；
- 证据 URI/hash；
- 允许访问的角色；
- 失败状态和复核时间。

M0 不接入任何聚合数据。

## 3. 明确禁止

- 行级会员身份、联系方式、画像、关系或行为记录。
- 行级健康咨询、病史、检查、诊断、建议或医患内容。
- 行级订单、支付、退款、余额、资金流水或交易主体信息。
- 行级客服工单、投诉、聊天、录音或附件。
- 凭据、秘密、生产环境变量。
- 可与外部数据轻易拼接并重新识别个人的“小样本聚合”。
- 任何通过前端隐藏代替服务端权限控制的实现。
- 任何由 dashboard 或 scheduler 发起的源系统写入。

## 4. 来源映射必填字段

每个未来事实或指标必须声明：

- `fact_id`
- 业务定义
- 唯一 authority
- source owner
- 只读接口或权威制品
- 数据等级
- 聚合口径
- freshness SLO
- 质量规则
- 统计时间窗
- 证据 URI/hash
- 允许角色
- permitted use
- 失败状态与原因码
- 下一复核时间

任一关键字段缺失即 `Unknown/No-Go`。

## 5. 失败关闭要求

出现以下任一情况时必须失败关闭：

- 来源不可达；
- 超出 freshness；
- 质量规则失败；
- 口径或权威冲突；
- Owner 缺失；
- 授权不足；
- 审计链断裂；
- 多个来源同时声称权威；
- 聚合阈值未配置或样本不足。

失败时不得补猜测默认值，不得静默沿用旧缓存。若展示最后可信快照，必须显著标注 `stale`、最后可信时间、失败原因以及责任 Owner，并声明不可用于当前决策。

## 6. 非功能要求

- 全链路只读、无回写端口。
- 最小权限和服务端授权。
- 刷新、访问、导出和发布均可审计。
- 口径、快照和权限配置版本化。
- 确定性构建与不可变快照。
- 明确时区、统计窗口和截至时间。
- 失败不覆盖最后可信快照。
- production routes、snapshots、jobs、dashboard 默认关闭。
- 代码集成、测试环境验证和生产启用分别审批。

## 7. M0 验收结果的权限边界

M0 Go 仅证明治理规则已冻结并允许另行建立 M1 工作项；它不授权 M1 合同之外的实现，也不授权 scheduler、dashboard、环境、部署、生产或真实数据。
