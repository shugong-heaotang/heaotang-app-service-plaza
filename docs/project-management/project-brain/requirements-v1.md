# 和奥堂 Project Brain v1 产品需求说明书

## 1. 产品定义

Project Brain 是和奥堂 APP 的内部项目控制系统。它把分散在代码仓库中的产品、架构、任务、决策、风险和验收事实汇总成可追溯视图，使项目负责人和新进入的 Agent 不依赖历史聊天即可理解项目并继续工作。

## 2. 目标用户

### 2.1 项目负责人

需要在一页内知道：项目总体是否健康、各模块做到哪里、哪些事项阻塞、哪些决策必须本人处理、哪些结果等待验收。

### 2.2 项目最高负责人 Agent

需要找到权威入口、全局依赖、当前活动范围、受保护路径、待派发事项和集成门禁。

### 2.3 开发与验收 Agent

需要获得与当前任务相关的最小上下文包，不读取无关秘密，不依赖过期聊天，不越过授权范围。

## 3. 核心原则

1. 一个事实只有一个权威来源；驾驶舱只聚合，不成为第二套台账。
2. 未验证、未知和缺失必须明确显示，不能推断为通过。
3. 状态必须有更新时间、下一检查点、责任角色和证据。
4. 高风险事项必须分离开发、复核和批准角色。
5. 所有自动结论必须能追溯到本地文件和具体字段。
6. 第一版失败关闭：来源不存在、格式错误或证据缺失时显示 No-Go/Unknown。

## 4. 功能需求

### PB-F01 统一入口

- 根入口说明产品边界、必读顺序、权威来源和当前版本。
- 新 Agent 能从入口定位模块、任务、决策、风险和验收资料。
- 入口不得复制动态状态数值，只引用生成的最新快照。

### PB-F02 知识地图

每条知识来源至少包含：

- `knowledge_id`
- 标题和类别
- 权威文件路径
- 责任角色
- 适用范围
- 最后复核时间
- 下次复核时间
- 当前状态
- 替代/上位来源（如有）

### PB-F03 模块登记

每个模块至少包含：模块 ID、名称、产品目的、负责人角色、父模块、依赖、当前阶段、开发状态、验收状态、下一检查点和权威状态来源。

首批模块：平台基础、服务广场、生命导航、俱乐部联盟、健康大管家、Nova AI。商城、课程、人脉等未形成权威事实时登记为 `planned` 或 `unknown`，不得虚构进度。

### PB-F04 决策队列

区分：

- 已作出的架构决定：引用 ADR；
- 等待项目负责人裁决的业务决定；
- 可由 Agent 按既定规则处理的普通决定。

待决策项必须包含问题、选项、建议、影响、风险、截止时间、批准角色和状态。

### PB-F05 风险登记

支持产品、运营、技术、安全、健康、支付、隐私、第三方和单点人员风险。每项风险包含概率、影响、责任角色、缓解措施、升级时间和关联任务。

### PB-F06 项目聚合

读取现有协作登记、模块登记、实现记录和风险/决策登记，生成规范化快照。不得回写原始权威文件。

### PB-F07 自动治理审计

至少检测：

1. 权威路径不存在；
2. 同一事实声明多个权威来源；
3. 活动任务缺少下一检查点或状态过期时间；
4. 活动工作范围重叠；
5. `integrated` 缺少独立验收或集成证据；
6. 高风险任务开发、复核和批准角色未分离；
7. 模块状态缺更新时间或来源；
8. 决策、风险或知识项已经过期；
9. JSON 不符合模式；
10. 驾驶舱快照比权威输入旧。

### PB-F08 老板驾驶舱

首版只读，提供：

- 总体结论：Go、Partial Go、No-Go、Unknown；
- 模块状态卡；
- 活动工作项与下一检查点；
- 阻塞与高风险；
- 待项目负责人决策；
- 待独立验收；
- 最近已集成成果；
- 数据生成时间和审计结果。

### PB-F09 来源追溯

每张卡片必须能显示来源路径、更新时间和证据状态。没有来源的内容不得展示为事实。

## 5. 权限需求

- 普通用户不能访问 Project Brain 路由。
- 第一版可先采用仅开发/测试环境启用的内部路由，生产默认关闭。
- UI 不提供写入、批准、部署和删除按钮。
- 敏感信息不得进入前端快照；账号、令牌、手机号、健康数据和支付数据只展示脱敏统计或不展示。

## 6. 成功指标

- 新 Agent 在十分钟内定位当前任务必读资料和权威状态。
- 项目负责人能在一页内找到全部待决策、高风险和待验收事项。
- 自动审计能阻止重复权威、过期活动项和无证据完成。
- 不新增第二套任务登记，不改变现有业务页面行为。
